# CLAUDE.md

Guidelines for working in this repository. They apply to people and agents alike.

## Project

RagAssembler is a browser-based ragdoll editor. RagImporter is its runtime library, for LiquidFun + PIXI.js.

## Sources of truth

| File | Role |
|---|---|
| `DESIGN.md` | **Spec index.** The spec itself lives in `docs/design/`, one file per section (`DESIGN.md` §N means the file listed for it). Read only the section file you need. Changes to behavior, file format or public API start there. |
| `docs/` | **How the code is built.** Architecture, modules, development setup, decisions. Must match the actual codebase. `docs/architecture.md` and `docs/decisions.md` are indexes: read only the file you need from `docs/architecture/` or `docs/decisions/` (use Grep on the index first). |
| GitHub issues | **Backlog.** One issue per task; one milestone per roadmap phase (`DESIGN.md` §11). Managed by `planner`. |
| `TODO.md` | Generated, read-only index of the issues. Regenerated by `doc-writer`; never edited by hand. |
| `CHANGELOG.md` | User-visible changes, [Keep a Changelog](https://keepachangelog.com/) format. |

If code and `DESIGN.md` disagree, stop and resolve it: either fix the code, or update the spec through the architect.

## Rules

1. **No AI attribution.** Never add Claude/AI credit anywhere: commit messages, `Co-Authored-By` trailers, "Generated with" lines, file headers, docs or changelog.
2. **No code comments.** Code must explain itself through naming and structure. No `//` or `/* */` notes, no commented-out code, no TODO comments (pending work goes in GitHub issues).
3. **Docstrings only.** Exported functions, classes, methods and typedefs get valid **JSDoc** (`/** … */` with `@param`, `@returns`, `@throws`, `@typedef`, `@property` as applicable). Keep them short: contract, units and side effects. Anything longer belongs in `docs/`.
4. **English** for code, docs, commits and file content.
5. **Confidentiality.** No client names, credentials, tokens or private data in the repo. Use generic terms and placeholders.

## Code conventions

- Vanilla JavaScript ES modules, no build step, no npm runtime dependencies.
- The only third-party code is `vendor/liquidfun.js` and `vendor/pixi.min.js`, pinned versions.
- Dependency direction (enforced):
  - `js/` (editor) may import `lib/`;
  - `lib/` never imports from `js/` or `demo/`;
  - `demo/` imports only `lib/`.
- Units follow `DESIGN.md` §1: meters, radians and Y up in data and physics; pixels and degrees only in the UI.
- Node 24 is used only for tests (`node --test`) and the local server.

## Git conventions

### Branches: [Conventional Branch](https://conventional-branch.github.io/)
- **One issue, one branch**, always created from an up-to-date `main`. Never commit directly to `main`.
- Format: `<type>/issue-<number>-<short-description>`. Lowercase, hyphen-separated, no other punctuation (dots allowed only in release versions).

| Type | Use |
|---|---|
| `feature/` | New functionality, e.g. `feature/issue-12-box-tool` |
| `bugfix/` | Bug fixes, e.g. `bugfix/issue-31-timeline-scrub-snap` |
| `hotfix/` | Urgent fix for a released version |
| `release/` | Release preparation, e.g. `release/v0.1.0` (no issue number) |
| `chore/` | Spikes, docs, tooling, dependencies, refactors without behavior change, e.g. `chore/issue-4-pin-pixi` |

### Commits: [Conventional Commits 1.0](https://www.conventionalcommits.org/en/v1.0.0/)
- Format: `<type>(<scope>): <description>`, imperative and lower-case, without a trailing period, e.g. `feat(editor): add box tool with shift/alt/ctrl modifiers`.
- **Keep it short.** Subjects stay brief (aim for 50–72 characters). Commit bodies and PR descriptions are concise: what changed and why, no narration or file-by-file lists.
- **Types:** `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `style`, `revert`.
- **Scopes:**
  - `editor` (`js/`, `index.html`);
  - `runtime` (`lib/`);
  - `format` (`.rag.json` schema, validation, serializer);
  - `demo`;
  - `tests`;
  - `docs`;
  - `deps` (`vendor/`).
- **Breaking changes:** `!` after the type/scope plus a `BREAKING CHANGE:` footer. This is required for any incompatible change to the RagImporter public API or the file format; file format breaks also bump the format `version` (`DESIGN.md` §6.3).
- No AI attribution in subject, body or trailers.

### Changelog: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/)
- Every branch with user-visible changes adds entries under `## [Unreleased]`, before merging. Sections: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`.
- Entries are written for users, one line each. They are not commit messages.
- Releases rename `[Unreleased]` to `## [x.y.z] - YYYY-MM-DD` on a `release/` branch. Versions follow [SemVer](https://semver.org/) derived from commits: `feat` → minor, `fix` → patch, breaking → major. Before 1.0.0, breaking changes bump the minor.

## Workflow

A task is a GitHub issue. It **closes when its pull request is merged into `main`**; the PR body says `Closes #<n>`, so GitHub closes the issue on merge.

1. **Pick:** run `/next`. It ranks the open issues by relevance (bugs, milestone order, unblocking power, risk, priority), recommends one, and creates its branch once confirmed.
2. **Spec check:** if the task changes behavior, the file format or the public API, or adds or changes a module, run `architect` first. It updates `DESIGN.md` and `docs/decisions.md` on the same branch.
3. **Implement** with the matching agent. A checkpoint is simply a conventional commit on the branch.
   - `javascript-dev` for the editor (`js/`), the runtime (`lib/`) and tests;
   - `game-dev` for `demo/` and real-game integration;
   - `ui-ux-analyst` reviews editor UI work, before (proposal) and after (review).
4. **Verify:** `node --test tests/` and run the app in the browser (`/run`). Use `/code-review` for non-trivial changes.
5. **Sync docs:** `doc-writer` updates `docs/` and `CHANGELOG.md`, regenerates `TODO.md` from the branch diff and issues, and commits as `docs: …`.
6. **Pull request and merge:** push, then open a PR whose **title is the Conventional Commit** for the whole task and whose body uses the PR template (`Closes #<n>`). Squash-merge it and delete the branch. The issue is now closed.

```powershell
git push -u origin feature/issue-12-box-tool
gh pr create --title "feat(editor): add box tool with shift/alt/ctrl modifiers" --body "Closes #12`n`n<summary and definition-of-done checklist from .github/pull_request_template.md>"
gh pr merge --squash --delete-branch
git switch main
git pull --ff-only
```

**New work** discovered during a task is not done on the current branch. Ask `planner` to file it as an issue.

### Definition of done (checked before merging)
- Behavior matches `DESIGN.md`, or `DESIGN.md` was updated by the architect on this branch.
- Tests pass, and the change was exercised in the browser when it touches the UI or runtime.
- No code comments; exported API has JSDoc.
- Modules, exports and imports conform to `docs/architecture.md`; PRs that add or change modules were reviewed by `architect`, who updated the module map on the branch.
- `CHANGELOG.md`, `TODO.md` and `docs/` reflect the change.
- The branch name, commits and PR title follow the conventions above, and the PR body closes the issue.

## Agents and skills

| Name | Kind | Use |
|---|---|---|
| `planner` | agent | Files and grooms GitHub issues, labels, milestones and dependencies. |
| `architect` | agent | Owns `DESIGN.md`, module boundaries and `docs/decisions.md`. |
| `ui-ux-analyst` | agent | Proposes and reviews editor interactions (read-only). |
| `javascript-dev` | agent | Editor, runtime and tests. |
| `game-dev` | agent | `demo/` and the game-developer view of the RagImporter API. |
| `doc-writer` | agent | Syncs `docs/`, `CHANGELOG.md` and the generated `TODO.md`. |
| `/next` | skill | Picks the most relevant open issue and creates its branch. |
| `/run`, `/code-review`, `/simplify` | built-in skills | Run the app, review a diff, clean up after a phase. |

**Models by role** (set in each agent's `model:` frontmatter):
- `opus` for agents that plan and decide: `architect`, `planner`, `ui-ux-analyst`.
- `sonnet` for agents that apply delegated changes: `javascript-dev`, `game-dev`, `doc-writer`. Complex implementation tasks may override to `opus` per call.
- `haiku` for pure search and reading delegation (built-in `Explore` or a per-call override).
