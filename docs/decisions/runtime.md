# Decisions: Runtime and format

Newest first. See the [index](../decisions.md).

## 2026-10-16
- **Implementer choices for #44.** The mirrored `aimAxis` of each joint is kept in a private `Map` on the instance until #48 reads it. `view` is `null` after `destroy()`. `configure` accepts no `contactFilter` key until #49. `RagFormatError` names the unsupported version only when `E_VERSION_UNSUPPORTED` is the first error; otherwise it gives the error count and the first code and path. Reason: no public surface for state nothing reads yet; a destroyed instance must not hold a PIXI container. (DESIGN §7.1, §7.2)
- **Spawn contract settled for #44.** Frames: body at `S × L′`, where `L′` mirrors the root-local transform with `M(p) = (−x, y)` and negated angle under `flipX`; shapes mirror in the body frame (centers, box angle, reversed polygon vertices); anchors map as `S × M(anchor)`. Every throw (missing library, bad `world` or options, locked world) happens before any native object exists; a native failure later rolls back joints, then bodies. Joints start with the motor off; `update()` enables it. Spawn uses one scratch `b2Vec2`, destroys each def and shape after its `Create*` call, and builds polygons from a `_malloc` buffer freed right after `Set`. Reason: one mirror rule yields the existing limit `(−upper, −lower)` and `aimAxis` `π − aimAxis` rules; failing early keeps the heap and world clean; a passive ragdoll (no `update()`) is what the editor's Pose tool (#145) needs; the polygon path needs a contiguous native array, which the binding offers only through the heap (to verify, DESIGN §12). (DESIGN §7.2, §7.4, §12)
- **`parse` copies, `RagFormatError` carries the problems.** `parse` deep-copies and freezes only the fields RagImporter consumes, so later edits to the source JSON (the editor's model export) never reach a definition. `RagFormatError` exposes frozen `errors` and `warnings`; its message names the unsupported version or the first error's code and path. Reason: an immutable `RagDef` must not alias caller data; codes and paths are the stable part of a problem. (DESIGN §6.3, §7.1)
- **`configure` semantics and library resolution.** `undefined` keeps a key, `null` returns it to the global, unknown keys are ignored, and nothing is checked until `spawn`. Resolution stays private to `lib/ragimporter.js`, which passes a resolver to each `RagDef`, so no new module is needed and it remains the only reader of the globals (docs/architecture.md, Dependency rules). Reason: tests and the editor can swap and reset namespaces without import cycles. (DESIGN §7, §7.1; docs/architecture.md, Module map)
- **Host access to native objects is defined.** The host may change dynamic state (transform, velocity, damping, awake, gravity scale) and attach its own joints, which it destroys before `rag.destroy()`; it never touches fixtures, filter data, motors or limits. No damping or "pose" options are added to `spawn`. `destroy()` is idempotent, throws on a locked world, and leaves empty maps and `null` `position`/`angle`. Reason: the Pose tool needs zero gravity (host world), high damping (`SetLinearDamping`/`SetAngularDamping` after spawn), mouse joints (via `bodies`) and fast respawn, which the native handles already allow without growing the API. (DESIGN §7.1)
- **`spawn` gains a `baseUrl` option.** The default texture resolver already used `baseUrl + src` with no way to pass `baseUrl`. Reason: internal coherence of §7.1. (DESIGN §7.1, §7.3)
- **Validation details settled in #25.** `hasImage` receives the sprite asset id. A `rootBody` that points at a body whose id has an error reports `E_ROOT_BODY_UNKNOWN`. `E_JOINT_SAME_BODY` suppresses `W_ANCHOR_OUTSIDE` for that joint. `E_KEY_TIME_RANGE` is reported only for `t` above the clip length; a negative `t` is `E_FIELD_RANGE`. `W_DUPLICATE_NAME` is one warning per duplicated name within a kind, at the second occurrence, listing every colliding id; equal names across kinds do not warn. Reason: one problem per cause, no cascades. (DESIGN §6.4)
- **Validation problems are `{ severity, code, message, path, target }` with stable codes.** Every §6.4 rule has one `E_*` or `W_*` code with a fixed severity; codes are never renamed or reused. `path` is a JSON Pointer into the validated JSON, `target` is `{ type, id }` of the innermost selectable object (a clip by `key`) or `null`. Messages are English, unstable, and quote no length or angle values. An invalid input, wrong `format` or unsupported `version` stops validation after the gate; a field with an error is skipped by the rules that read it. Reason: the Problems panel (#26), load and save (#27, #28) and `parse` (#44) need machine-readable results that survive wording changes; JSON Pointer resolves duplicates and id-less objects (tracks, keys, events) by position, which ids cannot; data-unit numbers in messages would contradict the pixels-and-degrees UI. (DESIGN §6.3, §6.4, §7.1; docs/architecture.md, Validation, Module map)
- **`lib/validate.js` owns validation; `RagImporter.validate` delegates to it.** It exports `validate(json, options?)`, `SUPPORTED_VERSIONS` (also used for `RagImporter.supportedVersions`) and `PROBLEM_CODES`, and imports only `lib/schema.js` and `lib/geometry.js`. The only option is the editor's `hasImage(asset)`, which enables `W_SPRITE_IMAGE_MISSING`; the public `RagImporter.validate(json)` takes none. Reason: one implementation shared by editor and runtime, pure and testable under Node; image availability is editor state that a pure module cannot see. (DESIGN §6.4, §7.1; docs/architecture.md, Validation, Module map)
- **Schema ranges apply unconditionally: `limits.lower ≤ 0` and `limits.upper ≥ 0` hold even when limits are disabled.** §6.4 said "when limits are enabled". Not a format version bump: `lib/schema.js` already declares the bounds unconditionally, the editor's defaults and Hinge tool always satisfy them, and no `.rag.json` has been saved yet (Save is #27). Reason: one generic range check instead of a conditional hand-written one, and `flipX` and re-enabling limits never meet an inverted range. (DESIGN §6.4; docs/schema.md)
- **Unknown fields and duplicate names are validation warnings** (`W_UNKNOWN_FIELD`, `W_DUPLICATE_NAME`; bodies, shapes and joints, each kind on its own), and runtime name lookups return the first match in file order. Reason: the editor's "drop with a warning" (§6.3) needs a source, and `rag.body/joint/shape/sprite(name)` and `lookAt` resolve by name, so a repeated name silently picks one object. #25 covers the validation side of #78. (DESIGN §6.3, §6.4, §7.1)
- **Polygon validity is checked in the order count, degenerate (vertices closer than 0.0025 m or collinear within 1e-9 m²), clockwise, not convex (including stars that wind twice), with one error per polygon; anchors count as inside within 0.001 m.** Reason: one actionable error at a time; a signed-cross test alone accepts a pentagram; an anchor placed exactly on a shared edge must not warn through rounding. Thresholds to verify against the pinned build (DESIGN §12). (DESIGN §6.4, §12; docs/architecture.md, Validation)

## 2026-10-14
- **RagImporter owns one contact filter per world, and the host plugs into it.** Its `ShouldCollide` reimplements Box2D's default group/category/mask rule (bit fields `& 0xffff`), then the self-collision rule through a registry keyed by fixture pointer, then an optional host predicate set with `RagImporter.setContactFilter(world, predicate)`; a pair collides only if all three allow it. The filter is installed on the world's first `spawn` or `setContactFilter`, stays installed when the last instance goes, and is uninstalled and destroyed only by the new `RagImporter.releaseWorld(world)`, called right before the host destroys the world. Instances remove their registry entries before `DestroyBody`. The `groupIndex` fallback stays for builds without `JSContactFilter` and for hosts that opt out with `configure({ contactFilter: false })`. Reason: issue #4 spike (`tests/liquidfun-contact-filter.test.js`): a JS filter replaces the default rule, which the reimplementation matches; `userData` holds only an integer while the fixture pointer is stable and is what `ShouldCollide` receives; there is no `GetContactFilter`, so a host filter cannot be chained, only replaced; `SetContactFilter(null)` leaves no filtering at all, so uninstalling with the last instance would silently break the host's own category/mask rules; the cost is about +8 % step time for 20 humanoids. Hosts that need to collide pairs the default rule excludes cannot express that as an AND-ed predicate, hence the opt-out. Not a format change. (DESIGN §2.5, §7.1, §7.2, §7.4, §7.5, §8, §12; docs/architecture.md, Module map)
- **The liquidfun.js API surface is confirmed, and RagImporter follows fixed native-memory rules.** The pinned build exposes everything §3 and §7.2 need; motor, limit and angle methods exist only on the `b2RevoluteJoint` wrapper, so spawn casts each joint once with `Box2D.castObject` and stores it. Filter `maskBits` reads back signed and is masked with `& 0xffff`. The heap is a fixed 16 MiB that cannot grow, and exhausting it aborts the module, so: copied defs, shapes and filters are destroyed right after use; world-owned objects and getter results are never destroyed; `update()` and `sync()` allocate nothing and reuse a scratch `b2Vec2`; joints are destroyed before bodies. Reason: issue #5 spike, verified in Node by `tests/liquidfun-api.test.js`; a per-step leak would abort a running game within minutes. (DESIGN §3, §7, §7.2, §7.4, §12)
- **The pinned build supports a JS contact filter (`JSContactFilter` + `SetContactFilter`), but its integration stays open in issue #4,** and the `groupIndex` fallback stays specified until then. Reason: one filter per world, shared by instances and the host, replaces Box2D's default filtering, which the spike did not verify. (DESIGN §2.5, §12) *Superseded by "RagImporter owns one contact filter per world" above: issue #4 settled the integration and verified the default-rule replacement.*
- **RagImporter is the `lib/` folder,** with `lib/ragimporter.js` as the only public entry. Hosts copy `lib/`; `demo/` imports only the entry; the editor may import internal `lib/` modules. Reason: schema, emitter, validation, serializer and evaluator must be shared, pure and testable, which one file would not allow at a reasonable size. (DESIGN §7, §8, §9)
- **liquidfun.js is the doebi/liquidfun.js v1.1.0 Emscripten (asm.js) build**, reached through its `Box2D` namespace global with WebIDL accessors; RagImporter never assumes global `b2*` names. `RagImporter.configure` accepts `{ Box2D }` as well as `{ PIXI }`, both optional. It is the build the project owner uses, is self-contained and matches the reference demo byte for byte; injecting the namespace mirrors the PIXI handling and lets tests and module-based hosts supply it without a global. (DESIGN §7, §12)
- **PIXI.js is pinned to 8.21.0** after verifying `Assets`, `sortableChildren`/`zIndex` and `eventMode` + `pointermove`. (DESIGN §7, §12)
- **RagImporter targets LiquidFun + PIXI.js directly**, with no engine/renderer adapter layer. The project only targets this stack; an adapter layer can be added later if needed. (DESIGN §7)
- **Procedural joint control lives in RagImporter**; authoring (`aimAxis`) and preview live in the editor. Targets come from runtime data the editor cannot key. (DESIGN §4.8)
- **Shapes carry sprites** (offset, angle, scale, z), and the timeline can swap them through a discrete `sprite` channel. (DESIGN §2.3, §4.2)
- **The root is a world object** that parents everything and owns the global `strength`/`gain`/`damping` channels. These are 0–1 multipliers, never overrides, so a "dead" clip needs a single track. (DESIGN §2.1)
- **Springs are emulated with joint motors** (PD over motor speed, torque scaled by strength), because LiquidFun revolute joints have no spring. (DESIGN §3)
- **Layers:** the higher index wins; override by default, additive optional; no masks, since a clip only affects the tracks it has. (DESIGN §4.4)
- **Transitions** use per-clip `fadeIn`/`fadeOut`; a transition matrix is backlog. (DESIGN §4.1)
- **Grouping replaces FixedJoint**: a body can have several fixtures. (DESIGN §2.2)
- **The editor's Simulate mode uses RagImporter**, so preview equals production. (DESIGN §3, §5.1)
