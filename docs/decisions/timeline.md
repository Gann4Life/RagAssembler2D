# Decisions: Animation timeline

Newest first. See the [index](../decisions.md).

## 2026-11-05 (issue #218, Multiplier tracks)
- **Lanes become groups with sub-tracks.** One group per target with tracks (Root first, joints in `joints` order, then sprite shapes); a header row with a ▾ / ▸ collapse button and an empty lane, then one row per track in fixed channel order, keyless tracks included. Collapse is session UI state per target, not saved or undoable, and changes no selection; the Summary row keeps covering hidden keys. Reason: multiplier tracks need per-channel rows; the flat joint-angle rows cannot show them. (DESIGN §5.8)
- **"+ Track ▾" in the Timeline bar and a 🗑 per sub-track row**, both visible and disabled with reasons; target is the selected joint, or the root when it or nothing is selected; one undo step each. Reason: every action needs a visible control; nothing-selected already means the root in the inspector. (DESIGN §5.8)
- **Multiplier key values are edited on the inspector's Key page `value` row** (%, 0–100, invalid values revert), the page #174 already specifies; mixed value kinds show `—` read-only. Double-click inserts a key with the track's evaluated value (keyless: the channel's neutral value) and selects it, so the value can be typed at once. Key tooltips show the value in display units. Reason: no new control that the Key page would duplicate later; drag-to-edit has no visible affordance. (DESIGN §5.7, §5.8)
- **No format or runtime change.** Multipliers are already 0–1 in §4.2/§6.2 (`E_KEY_VALUE`), new keys default to `linear` (§4.3), and `resolveChannels` already applies joint and root multipliers to every motor and root multipliers to the balance controller, in RagImporter and in the editor's clip simulation, which runs RagImporter. Pose and Key selected keep writing only `angle` / `bodyAngle` keys. (DESIGN §4.2, §4.3, §4.4, §5.8)

## 2026-11-05 (issue #203, Timeline summary row)
- **One Summary row at the top of the key lanes, no per-group rows.** It summarizes every key drawn in the lanes (collapsed groups included, events excluded); keys within 1e-6 s, the commands' same-time tolerance, share one summary key. Reason: dope-sheet convention, and the owner wants it simple; the lanes are flat joint rows today, so per-group summaries add nothing yet. (DESIGN §5.8)
- **A summary key is a group proxy for its keys under the key rules.** Outlined, half filled or filled for none, some or all selected; click modifiers (none, SHIFT toggle, CTRL remove, read at the press) apply to its keys as a group; only a fully selected summary key drags, moving the whole selection through `moveKeys` (same snapping, clip clamp and same-track replacement, one undo step); Delete keys acts on the selection. Reason: one selection model and one move command, no summary-specific state or hotkeys. (DESIGN §5.8)
- **Key click modifiers made explicit and read at the press**, matching the Hierarchy: none selects only an unselected key and keeps an existing selection otherwise, so a drag moves it; SHIFT toggles; CTRL removes. Reason: §5.8 only said "SHIFT multi-selects", and the summary row needs the same rules. (DESIGN §5.8)
