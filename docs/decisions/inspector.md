# Decisions: Inspector

Newest first. See the [index](../decisions.md).

## 2026-11-05 (Document and Ragdoll pages, #218, owner decision)
- **An empty selection shows a Document page (`pixelsPerMeter`, preview gravity); a selected root shows the Ragdoll page without them (name, id, locked transform, `rootBody`, Drive strength / balance / gain / damping ◇, body angle, the "Balance controller" group).** One page builder may serve both with sections chosen by context. Reason: the owner found document settings out of place on the ragdoll node. "+ Track" with nothing selected is now disabled ("select one joint or the root"), since the empty-selection page no longer shows the root's channels. Supersedes the 2026-10-25 entry "An empty selection shows the Ragdoll (root) page". (DESIGN §5.7, §5.8)

## 2026-11-05
- **The Joint page carries the inspector's only rotation: a derived "rest angle" (#23).** It shows `bodyB.angle − bodyA.angle`; an edit turns the child body's subtree about the anchor (Select's ring on the joint without ALT, through `placeBodies`), read-only for a joint without child body or placed anchor. Reason: the owner put rotation on joints (#20); the rest angle is the one absolute value a joint has, so a typed value means the same for every joint. (DESIGN §2.4, §5.7)
- **No body swap or reassignment on the Joint page; `bodyA`/`bodyB` are read-only (#23, owner decision; #189 stays open).** Reason: joint angles will be driven by host code (procedural moves such as aiming at the cursor, `setJointAngle`); a swap negates the joint's signed angle, limits and keys, so it would silently break that code. §2.4 no longer promises a swap. #189 must rethink it with the procedural API in mind (e.g. allowed only when nothing references the joint's signed angle, or a convention that keeps code stable). (DESIGN §2.4, §5.7, §12)
- **Joint page fields (#23):** an anchor edit moves only the anchor (ALT-drag semantics); limits are valid when `lower ≤ 0` and `upper ≥ 0`; `motor.maxTorque` is read-only "auto (*value* N·m)" until user-set torque (#212); `maxSpeed` hints that it caps the correction only (#209). (DESIGN §3, §5.5, §5.7)

## 2026-10-25
- **The Body page shows only physical properties: no position and no angle (#20, owner decision).** A body is a rigidbody, invisible in the viewport; its shapes define its collision area. Transforms come from the viewport tools: selecting a joint rotates it with its children, selecting a shape rotates only that shape. Supersedes, for the inspector, the entry below on position and angle edits carrying the subtree. `placeBodies` and `rotationPivot` stay in `js/commands/transform.js` with their tests for the Joint page (#23), which needs subtree rotation about the joint anchor; `placeBodies` has no caller until then. (DESIGN §5.7; docs/architecture/inspector.md)
- **Pure inspector pages cache by `Model.revision`, never by subscribing (#20 review).** `Model` gains a read-only `revision` that grows before every `change` and `reset` emit; `js/inspector/root-page.js` keys its playhead evaluation on revision, clip and time. Reason: a listener registered as a side effect of building a page breaks the "pure, Node-tested core" contract of `js/inspector/*` and hides a subscription with no owner to remove it; a counter costs one field and serves any later pure cache. (docs/architecture/inspector.md, docs/architecture/document-model.md)
- **The inspector panel may import `HOTKEYS` from `js/hotkeys.js` to show an action's shortcut (#20 review).** Action buttons read "Set as root body (Shift+R)" through `actionTitle` and set `aria-keyshortcuts`, as the header, the Tools overlay and the menus do. Reason: every visible control states its accelerator; reading the binding table instead of a literal keeps the hint in step with `DESIGN.md` §5.9. UI → core import, no cycle. (DESIGN §5.7, §5.9; docs/architecture/inspector.md)
- **A vec2 props commit on several objects is one `setProps` per object in one undo step (#20 review).** Each object keeps its other component, so editing X of a mixed vector never copies one object's Y onto the others. (docs/architecture/inspector.md)
- **An empty selection shows the Ragdoll (root) page (#20, owner decision).** Reason: document settings (`pixelsPerMeter`, preview gravity, multipliers, balance) stay one glance away; showing the page does not select the root. *Superseded by the 2026-11-05 Document and Ragdoll pages entry.* (DESIGN §5.7; docs/architecture/inspector.md)
- **Superseded for the inspector by the Body-page-is-physics-only entry above: position and angle edits of a body carry its subtree, as a Select move or rotation without ALT (#20).** An angle edit turns the subtree around the parent joint's anchor, the pivot of Select's rotation ring (`rotationPivot`, moved to `js/commands/transform.js`), so the body stays connected and its position field changes accordingly; `rootBody` and bodies without a parent joint turn around their origin (owner decision). Several bodies are placed one after the other, a selected ancestor before the bodies of its subtree and otherwise in selection order, so each ends at the typed value (amended in the #20 review: plain selection order let an ancestor placed later move an already placed descendant). Reason: Select moves subtrees by default and editor operations act on the hierarchy; a plain `setProps` would tear bodies away from their joints and leave anchors behind. Trade-off: no inspector equivalent of ALT (move one body alone); the Select tool still offers it. (DESIGN §5.5, §5.7; docs/architecture/inspector.md)
- **The inspector is a core page model plus a thin panel (#20).** `js/inspector/*` (core, Node-tested) builds pages, rows, read-only reasons and commit commands; `js/panels/inspector.js` renders and routes commits. Each later object type adds one page module and one `PAGE_BUILDERS` entry (#21, #22, #23, #34, #172, #174). Reason: mode rules, mixed values, unit conversion and commit commands are the error-prone part and must be tested without a DOM, as the timeline does with `js/timeline-rows.js`. (docs/architecture/inspector.md)
- **The `rootBody` dropdown goes through `Editor.setRootBody(bodyUid)`, shared with the `set-root-body` action (#20).** Actions take no argument and act on the selection, while the dropdown names any body; one editor method keeps one refusal rule, undo step and status message. `(none)` is shown while `rootBody` is `null` and cannot be chosen, since `setRootBody` never clears it. (DESIGN §5.6, §5.7)
- **Until key buttons exist (#39), animatable fields in Animate show the evaluated value read-only; Simulate shows document values read-only, not the live state; `balance.maxTorque` is read-only "auto" like a joint's `maxTorque`.** Reason: editing a channel in Animate means writing a key, which is #39's feature; a live readout in Simulate has no edit and would redraw every frame for little use; the automatic torque overwrites `balance.maxTorque` on every rig change, so an editable field would silently lose the user's value. (DESIGN §5.1, §5.7, §12)
