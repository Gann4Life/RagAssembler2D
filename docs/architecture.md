# Architecture

> Status: partly built. The editor shell (header toolbar, dock with placeholder panels, Window menu, Settings popover), the viewport (camera navigation, framing, adaptive grid, shapes of the rest pose, display modes), the editor core (document model, command stack, property edits, selection, modes, actions and hotkeys, editor settings, camera, framing bounds, grid geometry, snapping rules, UI unit conversions), the #12 core (tool table and registry, hit testing, displayed-pose placement, viewport style constants, overlay settings, tool hotkey rows) with its emitter, property schema and the `lib/geometry.js` functions of #11 and #12, a stub of `lib/ragimporter.js`, the test harness with the architecture conformance tests and the pinned `vendor/` libraries exist. Everything marked **(planned)** is the agreed design that issues implement; it is updated as code lands. Changes to this design go through the architect ([Conformance](#conformance)).

RagImporter reaches liquidfun.js only through the `Box2D` namespace (no global `b2*` names) and PIXI.js through `PIXI`; either can be injected with `RagImporter.configure({ Box2D, PIXI })` **(planned)** ([`DESIGN.md` §7](../DESIGN.md#7-ragimporter)). Both libraries are pinned in `vendor/` ([Vendored libraries](development.md#vendored-libraries)). Every runtime module that creates or destroys LiquidFun objects follows the native memory rules ([`DESIGN.md` §7.4](../DESIGN.md#74-native-memory)): the heap is fixed and cannot grow.

`demo/` is a separate host page **(planned)**. It imports only `lib/ragimporter.js` and the vendored libraries.

## Editor boot

1. `index.html` loads `css/editor.css`, then the vendored libraries as classic scripts: `vendor/pixi.min.js` (defines `PIXI`) and `vendor/liquidfun.js` (defines `Box2D`).
2. It loads `js/main.js` as the only module script. The markup holds a placeholder `<header id="header">` and `<main id="workspace">` with the viewport panel (`#panel-viewport` > `#viewport-host`, `role="group"`, `tabindex="0"`, labelled "Viewport"; [`DESIGN.md` §5.4](../DESIGN.md#54-viewport)). The viewport switches the host to `role="application"` once it handles keys (step 11).
3. `js/main.js` reads the `PIXI` and `Box2D` globals and throws an `Error` naming the missing library and its `vendor/` file. The error only reaches the console; the page stays blank.
4. It restores the editor settings with `Settings.restore(loadSettings().value)`: a `parse` error and every returned warning go to `console.warn`, and `missing`/`unavailable` give the defaults silently.
5. It calls `createEditor({ settings })` ([Editor composition](#editor-composition)): model, history, selection, modes, the core actions, the settings and the camera, without DOM. It saves with `saveSettings(settings.toJSON())` on every `settings` event.
6. It replaces the placeholder with `createHeader(document)`: a toolbar with every action disabled ([`DESIGN.md` §5.3](../DESIGN.md#53-header)). The Settings button gets `aria-haspopup="dialog"` and `aria-expanded="false"`.
7. It creates the dock with `createDock(#workspace, { viewportElement: #panel-viewport })`, which restores the stored layout (falling back to the default layout if restoring throws) and renders every stack, with placeholders for the panels ([Dock layout](#dock-layout)).
8. It registers the DOM actions on `editor.actions`: `window` (toggles `openMenu(windowButton, dock.windowItems(), …)` on its first item), one `panel:<id>` per `PANELS` entry (opens or closes the panel) and `reset-layout`. Choosing a Window menu item calls `actions.run('panel:<id>')` or `actions.run('reset-layout')`; Left/Right from the menu call `focusAdjacentAction(header, windowButton, key)`. Down and Up on the Window button open the menu on its first or last item (handled on the button, not as actions).
9. It refreshes every header button with `setActionEnabled(button, actions.isEnabled(id), actions.reason(id))`, once and then on every `history`, `mode`, `selection` and model `reset` event, and routes every `header-action` to `actions.run(id)`. On `history`, `mode` and `reset` it also calls `refresh()` on the open Settings popover, so its pixels per meter value and read-only state follow undo, mode changes and gestures.
10. It adds one `keydown` listener on `document` that calls `dispatchKey(event, { actions, tools: null, viewportFocused })`, where `viewportFocused` means focus is inside `#viewport-host` ([Actions and hotkeys](#actions-and-hotkeys)).
11. It awaits `createViewport(PIXI, #viewport-host, { model, camera, settings, insets, onSpaceTap: () => actions.run('toggle-play') })` ([Viewport camera, grid and snapping](#viewport-camera-grid-and-snapping)); `insets` returns 16 px on every side.
12. It registers `settings`, `frame-selection` and `frame-all`, then refreshes the header once more.

`Box2D` is checked but not used yet. The DOM actions are registered in `js/main.js` because they need the dock, the header or the viewport; `js/editor.js` registers only DOM-free actions.

**(planned, #12)** `createEditor` also builds the tool registry (`editor.tools`) and registers the `tool:<id>` actions ([Tools](#tools)). Boot passes `tools: editor.tools` to `dispatchKey`, and `selection`, `modes` and `tools` to `createViewport`, which binds the registry to the view and adds the gizmo and tool overlay layers. Once the Tools overlay (#87) exists, `js/main.js` wires it to the registry: `onActivate(id)` → `actions.run('tool:' + id)`, and on every `tool` and `mode` event (and once at start) `toolbar.setActive(tools.active?.id ?? null)` and `toolbar.setEnabled(id, actions.isEnabled('tool:' + id), actions.reason('tool:' + id))` for every `TOOL_SPECS` id.

**(planned)** Boot grows: `main.js` mounts the panels and passes them the editor object, registers the other actions that need the DOM (file pickers, confirmations), and offers draft recovery ([`DESIGN.md` §1](../DESIGN.md#1-conventions)).

## Dependency rules

| From | May import |
|---|---|
| `js/` | `lib/`, other `js/` modules per the layers below. Only `js/main.js` reads the `PIXI` and `Box2D` globals; other modules receive them as parameters. |
| `lib/` | Other `lib/` modules only. Only runtime modules (`def`, `instance`, `render`, `collision`) use `Box2D`/`PIXI`, and only through the namespaces resolved by `lib/ragimporter.js`. |
| `demo/` | `lib/ragimporter.js` only (the public API), vendor globals. |
| `tests/` | `lib/`, `tests/helpers/`, `vendor/liquidfun.js` (loaded with `createRequire`, only by the liquidfun.js verification tests `tests/liquidfun-*.test.js`), and `js/` **core** modules (they load without a DOM). Exception: a `js/` UI module that loads without a DOM may be imported to test its DOM-free exports (`js/header.js`: `HEADER_GROUPS`, `actionTitle`; `js/viewport/toolbar.js` (planned): `TOOL_BUTTONS`), or with a fake browser global installed on `globalThis` for the test and restored after it (`js/storage.js` with a fake `localStorage`). DOM behavior is checked in the browser. |

**Layers inside `js/`:**

| Layer | Modules | Rules |
|---|---|---|
| Core | `js/editor.js`, `js/model/*`, `js/commands/*`, `js/modes.js`, `js/hotkeys.js`, `js/actions.js`, `js/units.js`, `js/settings.js`, `js/roving-focus.js`, `js/tools/*`, `js/viewport/camera.js`, `js/viewport/bounds.js`, `js/viewport/grid-lines.js`, `js/viewport/snap.js`, `js/viewport/hit.js`, `js/viewport/placement.js`, `js/viewport/style.js`, `js/panels/layout.js` | No DOM, no PIXI import, no globals. Load and run under `node --test`. Import only `lib/` and other core modules. Tools draw only through the `PIXI.Graphics` they are handed. |
| UI | `js/main.js`, `js/header.js`, `js/menu.js`, `js/viewport.js`, `js/viewport/*` (other than camera, bounds, grid-lines, snap, hit, placement, style), `js/panels/*` (other than layout), `js/settings-dialog.js`, `js/storage.js`, `js/files.js`, `js/asset-store.js` | May import core and `lib/`. Receive the editor object and `PIXI` as parameters. Panel content modules (`hierarchy`, `assets`, `problems`, `inspector`, `timeline`) never import each other or the dock modules (`js/panels/dock.js`, `js/panels/layout.js`); `js/main.js` mounts them into the element the dock gives for their panel. Never mutate the model directly. |

Pure modules (`lib/` pure set and the `js/` core) must not touch the DOM, PIXI or LiquidFun.

## Editor core

### Document model

`js/model/model.js` holds the document as a tree of nodes, in file units (meters, radians, Y up).

```
Node         { uid: number, type: NodeType, parent: number|null, collection: string|null, props: object }
NodeType     'root' | 'spriteAsset' | 'body' | 'shape' | 'joint' | 'clip' | 'track' | 'key' | 'event'
NodeSnapshot { uid?, type, props, children?: { [collection]: NodeSnapshot[] } }
```

- **Identity:** every node has a session `uid` (positive integer, never serialized, never reused in the session). Display objects, selection, change payloads and history refer to uids. `ROOT_UID` (1) is the root. File ids (`root`, `b_…`, `f_…`, `j_…`, `s_…`) are props, and references between objects (`bodyA`, `rootBody`, `target`, `sprite.asset`, key values) store file ids exactly as in the file.
- **Tree:** the root owns the collections `sprites`, `bodies`, `joints`, `clips`. A body owns `fixtures`, a clip owns `tracks` and `events`, a track owns `keys`. The root's props hold the `ragdoll` record fields plus the document fields `meta`, `units`, `preview` ([schema.md](schema.md#document-file-top-level)); `format` and `version` are not props (the serializer writes them). A shape's `sprite` is a prop (object or `null`), not a node. A new `Model` holds an empty document with schema defaults and emits nothing.
- **Props** are plain JSON values shaped like the file record minus child collections, and are frozen. A props key or a `set` path whose first segment names a child collection of the node type (`fixtures`, `tracks`, `events`, `keys`, and the root's `sprites`, `bodies`, `joints`, `clips`) is rejected. A change replaces the value at a dotted path, creating missing intermediate objects; `value: undefined` removes the key (inverse of a `set` on an absent path).
- **Read API:** `get(uid)`, `prop(uid, path)`, `children(uid, collection) → readonly number[]`, `uidOf(id)` (file id → uid; the first holder when a draft or invalid file duplicates an id), `clipByKey(key)`, `nextId(prefix)`, `on/off`.
- **`nextId(prefix)`** takes `'b'`, `'f'`, `'j'` or `'s'` and returns `<prefix>_<n>`, with `n` above every `<prefix>_<n>` string seen in any prop during the session (ids, references, key values, names), so a dangling reference is never bound to a new object. Counters only grow, and survive `reset` ([`DESIGN.md` §1](../DESIGN.md#1-conventions)). `root` cannot be generated.
- **Not enforced by the model:** unique ids and clip keys, the reserved `root` id on other nodes, names, ranges and references. These are command preconditions and validation rules (#25). The model only refuses to change the root id, to remove or move the root, wrong child types and moves into a node's own subtree.
- **Mutation:** only through `applyOps`, `batch` and `reset`. `applyOps` and `batch` are called by `js/commands/history.js` only, and `reset` by `js/model/io.js` only.
  - **`applyOps(ops, cause = 'do') → ReadonlyArray<Op>`** applies the ops in order, atomically: if one throws, the call is reverted and nothing is emitted. Input ops may leave out derived fields (`previous`, `index`, move `from`, remove `snapshot`/`parent`/`collection`, snapshot uids); the returned ops are complete and are what history records and inverts. Outside a batch it emits one `change` with the effective changes, or nothing when every op was a no-op (a `set` to a JSON-equal value, a `move` to the same slot). A no-op op is still returned.
  - **`batch(fn) → { ops, changes }`** runs `fn` with change emission deferred. Every `applyOps` inside it applies immediately (so later reads see it) and must use cause `do`. If `fn` throws, every op applied in the batch is reverted in reverse order, nothing is emitted and the error is rethrown. Otherwise it emits one `change` (`cause: 'do'`) with all effective changes in application order, if any, and returns the applied ops and those changes, both frozen. Batches do not nest, and `reset` inside a batch throws.
  - **`reset(snapshot, cause = 'new')`** replaces the document from a root snapshot and emits `reset`. Every node but the root gets a fresh uid, whatever uids the snapshot carries. On an invalid snapshot it throws and leaves the model unchanged.

### Commands and undo

Strategy: **command objects recorded as primitive operations**, not model snapshots ([decision](decisions.md)). `js/commands/history.js`.

```
Command      { label: string, run(tx: Transaction): * }
Transaction  { model, set(uid, path, value), add(parentUid, collection, index, snapshot) → uid,
               remove(uid), move(uid, parentUid, collection, index) }
Op           { op: 'set',    uid, path, value, previous }
             | { op: 'add',    snapshot, parent, collection, index }
             | { op: 'remove', snapshot, parent, collection, index }
             | { op: 'move',   uid, from: Slot, to: Slot }      Slot = { parent, collection, index }
HistoryState { canUndo, canRedo, undoLabel: string|null, redoLabel: string|null, dirty, gesture: boolean }
```

**`new History(model, { limit = HISTORY_LIMIT } = {})`**, `HISTORY_LIMIT = 200`. Members: `execute(command)`, `undo() → boolean`, `redo() → boolean`, `beginGesture()`, `endGesture() → boolean`, `cancelGesture() → boolean`, `markSaved()`, `state → HistoryState` (getters `canUndo`, `canRedo`, `dirty`, `inGesture` mirror it), `on/off('history')`. History never checks the mode policy; the actions and tools that call it do.

- **Commands are factories** in `js/commands/*.js` that return a `Command` (e.g. `setProps(uids, { 'limits.upper': 1.2 })`). They validate their preconditions and throw before mutating. `index` in `tx.add`/`tx.move` may be `undefined` (append).
- **`history.execute(command) → *`** runs `model.batch(() => command.run(tx))` and returns what `run` returned (e.g. a created uid). Each `tx` call is one `model.applyOps([op])`, applied immediately so `run` reads its own writes; `tx.add` returns the uid from the completed op. History keeps the completed ops each `tx` call returns, which carry their inverse data (`previous`, the removed subtree snapshot with its uids), and the model emits one `change` for the whole command. If `run` throws, the batch reverts the applied ops, nothing is recorded, no event fires and the error is rethrown. An execution with no changes records nothing (outside a gesture, the entry is discarded).
- **Inverse ops** are built by history from the recorded ops (the model's are private): `set` → `set` back to `previous`; `add` → `remove` of `snapshot.uid`; `remove` → `add` of `snapshot` at `parent`/`collection`/`index`; `move` → `move` to `from`.
- **Undo** applies the inverses of the top entry's ops in reverse order with one `model.applyOps(inverses, 'undo')`; **redo** re-applies the entry's recorded ops with one `applyOps(ops, 'redo')` and never calls `run` again, so file ids and uids are identical. Both return `false` (and do nothing) when there is nothing to undo/redo.
- **Compound operations are one command:** delete with cascade (joints, tracks, `rootBody` reassignment), group/ungroup, duplicate, create + assign `rootBody`, set key + create track. Whatever `run` does is one undo step.
- **Gestures** merge continuous edits. The tool registry opens one on a primary pointer press and closes it on release; inspector drag-scrubbing and sliders do the same.
  - `beginGesture()` throws if a gesture is already open. Every command executed while it is open is its own batch (one `change`, cause `do`) and appends its ops to the gesture's pending entry, labelled after its first command with changes.
  - **Coalescing:** a `set` op replaces an earlier `set` in the pending entry on the same `uid` and `path` (keeping the earlier `previous` and position, taking the new `value`) only when no op between them is a `set` on the same `uid` whose path is a prefix of that path or has it as a prefix (`sprite` vs `sprite.offset`), or an `add`/`remove` whose snapshot contains that `uid`. Otherwise it is appended. This keeps undo and redo exact when a gesture mixes whole-object and field sets.
  - `endGesture()` records the pending entry and returns `true`, except when it is empty or consists only of `set` ops whose `previous` is JSON-equal to their `value` (a drag back to the start): then nothing is recorded and it returns `false`.
  - A gesture **has changes** when `endGesture()` would record it: its pending entry is not empty and not made only of `set` ops whose `previous` equals their `value`. `canUndo`, `undoLabel` and `dirty` use this criterion, so a drag back to the start counts as no change.
  - `cancelGesture()` applies the inverses of the pending ops with one `applyOps(inverses, 'cancel')` (skipped when there are none), records nothing and returns `true`. Callers: Esc, tool switch, mode change, and `undo()` while a gesture is open, which only cancels it, undoes nothing else and returns `true` like `cancelGesture()`, even for a gesture without changes (the `undo` action is disabled then, since `canUndo` is false). `redo()` while a gesture is open does nothing. Without an open gesture, `endGesture()` and `cancelGesture()` are no-ops returning `false`, so they are always safe to call.
- **Stack:** at most `limit` entries; recording an entry beyond it drops the oldest. Recording an entry clears the redo stack; cancelled and discarded gestures do not, because the model is back where it was.
- **Saved point:** a new `History` treats the model's current state as saved, so a fresh editor is not dirty. `markSaved()` marks the current state as saved. `dirty` is `false` exactly when the model is at the saved state, reached again through undo/redo, and no gesture with changes is open. Once the saved state can no longer be reached (its entry dropped by the limit, or a new entry recorded while it was on the redo stack), `dirty` stays `true` until the next `markSaved()`.
- **Reset:** history listens to the model's `reset` event (there is no public `clear`): it drops an open gesture without reverting it, empties both stacks, and sets the saved point to the new document for causes `new` and `load`, or leaves it unreachable for `recover` (a recovered draft is unsaved).
- **Re-entrancy:** `execute`, `undo`, `redo`, `beginGesture`, `endGesture` (with a gesture open), `cancelGesture` (with a gesture open) and `markSaved` throw while another history call is in progress, i.e. from inside `run` or from a model `change` listener.
  - **Known limitation:** a command executed inside a gesture that removes the open clip makes `modes` emit `mode` from the model's `change` listener, and the editor's cancellation listener then calls `cancelGesture()` with the gesture open, which throws. The command is still recorded into the gesture and the error is rethrown to the caller. No #10 command removes nodes, and gesture owners (tools, scrubbing) only set and add. It is closed by the action rule in [Actions and hotkeys](#actions-and-hotkeys): actions that execute commands are disabled while a gesture is open.
- **Listener errors:** when a model listener throws, the model has already applied the change ([Document model](#document-model)). History still updates its stacks as if the call returned (for `execute`, from the ops it kept, once `run` returned), emits `history`, and then rethrows.
- **Event:** `history` with `HistoryState` after any call that changes it, only when it differs from the last one emitted. `canUndo` is true when the undo stack is not empty or an open gesture has changes; `canRedo` when the redo stack is not empty and no gesture is open; `gesture` while a gesture is open. `undoLabel`/`redoLabel` are the labels of the entries undo/redo would act on (the pending gesture's label while one with changes is open).
- **Not undoable:** selection, camera, layout, settings other than `pixelsPerMeter`, mode, playhead, tool. New and Load reset the model, which clears history.

**`setProps(uids, values, label = 'Edit properties') → Command`** (`js/commands/props.js`): `values` maps dotted paths to new values (`{ 'limits.upper': 1.2 }`), the same for every uid; each path is one `tx.set` per uid, in `uids` order. It throws before mutating when `uids` or `values` is empty, a uid is unknown, or a path's first segment is `id` (ids never change, [`DESIGN.md` §1](../DESIGN.md#1-conventions)). It does not check types, ranges or references (the inspector constrains input, validation reports the rest, #25). When `name` is set on a clip, key-follows-name ([schema.md](schema.md#clip-clips)) runs for each clip in `uids` order, with `otherKeys` read after the previous clips of the same command were updated, so renaming several clips at once still yields unique keys; an explicit `key` in `values` wins over the rule.

### Selection

`js/model/selection.js`: `new Selection(model)`. Getters `objects`, `timeline`, `focus`, `state → SelectionState`.

- **Lists:** `objects` holds uids of types `root`, `spriteAsset`, `body`, `shape`, `joint`, `clip`; `timeline` holds `key` and `event` uids. Both are frozen arrays in selection order without duplicates. `focus` (`'objects'` by default) names the list the inspector shows.
- **Operations:** `set(uids)` replaces, `add(uids)`, `remove(uids)`, `toggle(uid)`, `clear()` (both lists, focus kept), `has(uid)`. Each of `set`/`add`/`toggle` takes uids of one list only (mixing lists, unknown uids or other node types throw) and moves `focus` to that list; `remove` and `clear` never move it. An empty array names no list: `set([])` acts as `clear()` (both lists emptied, focus kept) and `add([])` does nothing. To empty one list only, callers use `remove` with that list's uids. `remove` ignores uids that are not selected.
- **Pruning:** on a model `change` it drops every uid with a `remove` change; on `reset` it clears both lists and sets `focus` to `'objects'`. Undo and redo never add to the selection.
- **Event:** `selection` with `SelectionState` after a call or prune that changed a list or `focus`, once per call.

### Editor composition

`js/editor.js`: `createEditor({ settings } = {}) → Editor` (frozen) builds, in this order, `model = new Model()`, `history = new History(model)`, `selection = new Selection(model)`, `modes = new Modes(model)`, `actions = new ActionRegistry()`, and adds `settings` and `camera = new Camera()`.

- **Cancellation first:** before anything else subscribes to `modes`, it subscribes the listener that cancels the operation in progress on every `mode` event: `history.cancelGesture()` now; from #12, the tool registry's listener, which calls `tools.cancel()` (below). Emitters run listeners in subscription order, so other `mode` listeners (Simulate start, #54) never see a half-done gesture.
- **Settings and camera:** `settings` is the given `Settings`, or `Settings.restore(undefined).settings` when omitted, so tests need no storage; anything else given as `settings` throws `TypeError` before anything is built, so a wrong restore result fails at boot instead of at the first `get`. Neither listens to `modes`, and neither is undoable. `js/editor.js` registers no viewport or settings action: `settings`, `frame-selection` and `frame-all` need the DOM or the viewport and are registered by `js/main.js` ([Viewport camera, grid and snapping](#viewport-camera-grid-and-snapping)).
- **#12 (planned):** right after `modes` (`settings` and `camera` subscribe to nothing), and before anything else subscribes to `modes`, it builds `tools = new ToolRegistry({ model, history, selection, modes, settings, camera }, TOOLS)`, where `TOOLS` is the list of built tool modules imported by `js/editor.js` (empty in #12). The registry's own `mode` listener, subscribed in its constructor, is then the first one, and the editor's `history.cancelGesture()` listener is removed: `tools.cancel()` cancels any open gesture, including one the registry did not open (an inspector scrub). `tools` is frozen into `Editor`.
- **Core actions** registered here: `undo` and `redo` (`isEnabled`: `modes.can('history')` and `history.canUndo`/`canRedo`; `reason`: the mode reason when the policy refuses, else `null`; `repeatable`) and `escape` (cancels an open gesture, else clears the selection; #12 makes it `if (!tools.cancel()) selection.clear()`). **#12** adds one `tool:<id>` action per registered tool: `run` → `tools.activate(id)`, `isEnabled` → `tools.canActivate(id)`, `reason` → the mode reason for the tool's `capability`. They never execute commands, so they stay enabled during a gesture, and switching tools cancels it. Tools in `TOOL_SPECS` that are not registered have no action, so their hotkey and button report "not available yet". `undo` is unchanged: when it cancels a tool's gesture, the registry sees the gesture close and cancels the tool ([Tools](#tools)). Actions whose feature is not built are not registered, so they report `'not available yet'`; `play`, `pause`, `next-frame`, `stop` and `toggle-play` arrive with #54, mode switching UI with the Timeline (#32).

### Change notifications

All emitters are `lib/emitter.js` instances owned privately; owners expose `on` / `off` only.

| Source | Event | Payload | When |
|---|---|---|---|
| `model` | `change` | `{ changes: Change[], cause: 'do' \| 'undo' \| 'redo' \| 'cancel' }` | Once per committed transaction (`batch`), undo, redo, merge step or cancelled gesture, after the model is consistent. Not emitted when nothing changed. |
| `model` | `reset` | `{ cause: 'new' \| 'load' \| 'recover' }` | After the whole document was replaced. Views rebuild. |
| `history` | `history` | `HistoryState` ([Commands and undo](#commands-and-undo)) | After a call that changed it. |
| `selection` | `selection` | `SelectionState` `{ objects: number[], timeline: number[], focus: 'objects' \| 'timeline' }` | After any selection change. |
| `modes` | `mode` | `{ mode: 'edit' \| 'animate' \| 'simulate', previous, clip: number \| null }` (`previous` is the previous mode) | Mode or open clip changed. |
| `modes` | `playhead` | `{ time }` (s) | Playhead moved. |
| `tools` | `tool` | `{ id, previous }` (tool ids, or `null` for no active tool) | Active tool changed. |
| `settings` | `settings` | `{ key, value, previous }` | An editor setting changed. |
| `camera` | `camera` | `{ center, scale, width, height }` | After a pan, zoom, frame or size change that changed any of them. |
| `RagInstance` | `event`, `start`, `loop`, `complete`, `stop` | [`DESIGN.md` §7.1](../DESIGN.md#71-api) | During `rag.update(dt)`. |

```
Change = { kind: 'add',    uid, type, parent, collection, index }
       | { kind: 'remove', uid, type, parent, collection, index }
       | { kind: 'set',    uid, type, path, value, previous }
       | { kind: 'move',   uid, type, from: Slot, to: Slot }
```

Adding or removing a subtree produces one change per node: parents before children on `add`, children before parents on `remove`. Changes are listed in application order, and one event may add and then remove the same uid; listeners process them in order.

### View sync

`js/viewport/scene.js` never rebuilds the scene on a change. Built with #11: layers, camera transform, root, body and shape entries, display modes and the pose override. Sprite entries come with #21, and FK re-evaluation with the Animate issues. Joints, gizmos and highlights are not scene entries: #12 draws them in `js/viewport/gizmos.js` (planned).

- It keeps `Map<uid, Entry>` for root, bodies and shapes (sprites from #21). Layers, bottom to top: grid (a separate view from `js/viewport/grid.js`, added to the stage under the scene view), sprites (flat container, `sortableChildren`, `zIndex = z`, because z is ordered across the whole ragdoll), shapes (root container → body containers → shape graphics), gizmos, overlay (screen space). Sprites, shapes and gizmos live in the world container; the `gizmos` and `overlay` containers are empty.
  - **(planned, #12)** The scene drops its empty `gizmos` and `overlay` containers. `js/viewport.js` stacks two more screen-space views on the stage above the scene view: the gizmo layer (`js/viewport/gizmos.js`: feedback outlines, root and joint gizmos, overlays) and the tool overlay (the active tool's `drawOverlay`). Stage order: grid, scene, gizmos, tool overlay.
- On `change`: `add` creates the entry, `remove` destroys it, `move` reparents it, `set` marks it dirty with the smallest effect: root or body transform → container transform plus that body's sprites; shape geometry or `editor.color` → redraw that shape; `sprite.*` → that sprite; `units.*` on the root → world container re-placed and every entry dirty (still no rebuild). Joint changes touch no scene entry; the gizmo layer redraws on every model `change`. Clip, track, key and event changes only re-evaluate the FK pose when they belong to the open clip in Animate mode.
- Dirty entries are flushed once per frame from `PIXI.Ticker.shared`, which the viewport's application also renders from (`sharedTicker: true`), so a flush always precedes the render of its frame. `reset` is the only full rebuild; it clears the pose override, and the scene's `reset` listener runs before the viewport's, so framing after a reset uses the rest pose.
- Malformed shapes (non-finite numbers, non-positive radius, fewer than 2 polygon vertices, unknown type) draw nothing; an invalid `editor.color` falls back to the schema default; an invalid `pixelsPerMeter` falls back to the schema default for display.
- Conversion follows [`DESIGN.md` §1](../DESIGN.md#1-conventions): `x·ppm`, `−y·ppm`, `rotation = −angle`. The world container holding the sprite and shape layers carries the camera: `scale = camera.scale / ppm` and position `(width/2 − center.x·camera.scale, height/2 + center.y·camera.scale)`, so pan and zoom never redraw entries. The grid and overlay layers are in screen space. **(planned, #12)** The gizmo and tool overlay layers are in screen space too and, like the grid, are redrawn from a `PIXI.Ticker.shared` callback, at most once per frame, when dirty (a camera change included); they keep constant CSS px sizes without depending on the scaled-stroke technique.
- Outlines stay 1 CSS px at every zoom: shapes are stroked with width `ppm / camera.scale` (local units) and redrawn, once per frame, when `camera.scale` changed since the last draw (to be verified, [`DESIGN.md` §12](../DESIGN.md#12-open-items--to-verify)).
- `setPose(pose | null)` overrides body transforms (a root-local `Pose`, `js/viewport/bounds.js`) for FK preview without touching the model; `pose()` returns the current override, which framing uses, and from #12 hit testing and gizmos too (whoever calls `setPose` also calls `gizmos.invalidate()`). Simulate mode shows the `RagInstance` view instead (#54), and also sets the live root-local body transforms as the pose every frame, so hover, selection and gizmos follow the bodies. The preview environment (ground line, pin `rootBody`, gravity; [`DESIGN.md` §5.4](../DESIGN.md#54-viewport)) is built with Simulate mode (#54) and Pose (#38), not with #12.
- `display.mode` sets layer visibility and the shape style ([`DESIGN.md` §5.4](../DESIGN.md#54-viewport)) and redraws shapes; it never touches the model or hit testing. Shapes: sprites layer hidden, shapes filled at 0.4 and stroked at 1. Both: sprites shown, shapes stroked at 0.6 without fill. Sprites: the whole shapes layer is hidden, so the hover and selection outlines that §5.4 keeps in this mode are drawn by the gizmo layer (#12), which draws them in every display mode.
- Selection, hover, mode and settings changes redraw gizmos and highlights only.

### Viewport camera, grid and snapping

Behavior: [`DESIGN.md` §5.3](../DESIGN.md#53-header) (Settings) and [§5.4](../DESIGN.md#54-viewport). Everything numeric is core and tested under Node; the DOM and PIXI parts only route events and draw.

| Concern | Core (Node-tested) | UI |
|---|---|---|
| World ⇄ screen, pan, zoom, limits, framing fit | `js/viewport/camera.js` | `js/viewport/input.js` (pointer, wheel, keys), `js/viewport.js` (host size, insets) |
| What is framed | `js/viewport/bounds.js`, `lib/geometry.js` | `js/viewport.js` (`frame(uids)` with `scene.pose()`) |
| Grid levels and lines | `js/viewport/grid-lines.js` | `js/viewport/grid.js` |
| Snapping | `js/viewport/snap.js` | tools, through `ToolContext` |
| Settings values | `js/settings.js` | `js/settings-dialog.js`, `js/storage.js` |
| Display modes | `js/settings.js` (`display.mode`) | `js/viewport/scene.js` |

- **Ownership.** One `Camera` and one `Settings` per editor, owned by the composition root and exposed as `editor.camera` and `editor.settings` ([Editor composition](#editor-composition)). `js/main.js` restores settings with `Settings.restore(loadSettings().value)` before creating the editor (`restore(undefined)` gives the defaults; a `parse` error and the returned warnings go to `console.warn`) and passes them as `createEditor({ settings })`; it saves with `saveSettings(settings.toJSON())` on every `settings` event.
- **Actions.** `js/main.js` registers the three viewport and settings actions, because they need the DOM or the viewport: `settings` (toggles the Settings popover anchored to the header button; closing it this way returns focus to the button), `frame-selection` (`viewport.frame(selection.objects)`; `frame` falls back to everything when `framingBounds` returns `null`, which covers an empty selection and one with nothing to frame, [`DESIGN.md` §5.4](../DESIGN.md#54-viewport)) and `frame-all` (`viewport.frame(null)`). All three are enabled in every mode (`settings.editor` and `camera` capabilities) and never execute commands, so they stay enabled during a gesture. They are registered after `createViewport` resolves, followed by one header refresh; until then they report "not available yet". `F`/`Home` reach them through the existing `HOTKEYS` rows.
- **Insets.** `createViewport` takes `insets: () => Insets`, read at every framing; `js/main.js` returns 16 px on every side. The Tools overlay issue (#87) adds its `width()` to the left inset ([`DESIGN.md` §5.4](../DESIGN.md#54-viewport)).
- **Popover refresh.** The Settings popover follows `settings` events itself, but its document values come through the adapter, so `js/main.js` calls its `refresh()` on `history`, `mode` and model `reset` events ([Editor boot](#editor-boot)). The popover never subscribes to the model, history or modes.
- **Redraw scheduling.** The grid and the scene mark themselves dirty on events and redraw from a `PIXI.Ticker.shared` callback; `createViewport` inits the application with `sharedTicker: true` so that render runs on the same ticker after them (render is added at low priority). No ticker is passed to `createGrid` or `createScene`; they must only be used inside an application created this way (to be verified, [`DESIGN.md` §12](../DESIGN.md#12-open-items--to-verify)).
- **Camera rules.** `zoomAt` clamps `scale` first, then moves `center` so the world point under `screenPoint` stays there. `panBy` moves `center` by the screen delta divided by `scale` (Y flipped). `setSize` keeps `center` and `scale`. `frame(aabb, insets)` picks the largest `scale` that fits the box into the inset rect (at least 1 px each way), clamped, and centers the box in it. `center` is clamped after every operation. Every operation emits one `camera` event when something changed.
- **Snapping in tools.** `ToolContext.snapPoint`, `snapLength` and `snapAngle` are `snap.js` bound to `editor.settings`. Tools apply them as [`DESIGN.md` §5.4](../DESIGN.md#54-viewport) lists; the creation and Manipulate tool issues own that wiring.

- **`defineTool(definition)`** takes `{ id, ...members }`, throws `Error` for an id not in `TOOL_SPECS`, copies `label`, `hotkey`, `capability` from it (those keys in the definition are ignored, as is any member not in the contract), fills missing members with defaults (`cursor` `'default'`, `hover` `true`, no-op handlers, `keyDown`/`cancel` returning `false`), throws `TypeError` when a given handler is not a function, `cursor` is not a string or `hover` is not a boolean, and freezes the result. Tool modules export a **factory** (`circleTool() → Tool`) whose in-progress state lives in its closure; `createEditor` calls each factory, so every editor, and every test, has its own tool state.
- **Tools** are core: no DOM, no PIXI import; they draw only on the `Graphics` they are handed, with `js/viewport/style.js` colors and sizes. They read the model, mutate it only with `ctx.history.execute(command)` (never `beginGesture`, `endGesture` or `cancelGesture`), and keep in-progress state (polygon vertices, a drag rectangle) local until it becomes data. `ctx.modes.can(capability)` decides what an operation may do (e.g. Manipulate rotates into keys in Animate). Grid snapping is applied to world points before `toLocal`, so snapped points sit on the world grid ([`DESIGN.md` §5.4](../DESIGN.md#54-viewport)).
- **Creation tools** preview in `drawOverlay` and execute one create command when the operation completes (inside the release's gesture, so it is one undo step), then call `ctx.selection.set([uid])` with the uid the command returns (`history.execute` returns `run`'s value) and stay active. Aborted or refused operations execute nothing and leave the selection alone.

**`new ToolRegistry(core, tools)`**, `core` = `{ model, history, selection, modes, settings, camera }`, `tools` = `Tool[]` (an id twice throws).

- **Queries:** `list()` (registered tools in `TOOL_SPECS` order), `get(id) → Tool | null`, `has(id)`, `active → Tool | null`, `canActivate(id)` (registered and `modes.can(capability)`).
- **Start:** `select` is active when registered, else no tool (`active === null`; before #13 lands, and the toolbar then shows no pressed button). No `tool` event at construction.
- **`activate(id) → boolean`:** `false`, with no change, when `!canActivate(id)`. `true` with no change when `id` is already active. Otherwise `cancel()`, `deactivate()` the old tool, `activate(ctx)` the new one, apply its cursor, invalidate the overlay, emit `tool` `{ id, previous }` (`previous` is an id or `null`).
- **`pointer(input: ToolPointerInput)`:** fills `world = camera.screenToWorld(screen)` and `local = toLocal(world)`; ignored with no active tool.
  - `down`, button 0: ignored while a press is open and not cancelled. A cancelled press ends here (below). Then ignored while `history.inGesture` (a gesture owned elsewhere); else opens the press, `history.beginGesture()`, `tool.pointerDown(e)`.
  - `down`/`up`, button 2: passed to the tool without a gesture, unless a left press is open, cancelled or not (then ignored).
  - `move`: passed to the tool, hover moves included. While the press is cancelled, moves with the primary button held (`buttons & 1`) are swallowed.
  - `up`, button 0, of the open press: closes the press, `tool.pointerUp(e)`, then `history.endGesture()`. The release of a cancelled press is swallowed.
  - **A cancelled press ends** at its release, at the first `move` without the primary button (that move then reaches the tool), or at the next left `down`, whichever comes first, so a release lost after a cancel (capture already gone) never blocks the next press.
  - **A handler that throws** during a press (`pointerDown`, `pointerMove`, `pointerUp`, `keyDown`) aborts it like Esc: `cancel()` runs (for `pointerUp`, after the press was closed, so `tool.cancel()` and `history.cancelGesture()` revert whatever the release executed and nothing is recorded), then the error is rethrown. Outside a press (hover moves, right button, keys) errors are rethrown without a cancel.
- **`key(event) → boolean`:** `false` with no active tool or for `Escape` (and the legacy `Esc` key value; Esc always reaches the `escape` action); else `tool.keyDown` of the converted `ToolKeyEvent`, `true` only when it returns `true`. Tools consume only keys their issue documents, never tool hotkeys or §5.9 keys.
- **`cancel() → boolean`:** marks an open press as cancelled (its remaining events are swallowed), calls `tool.cancel()`, then `history.cancelGesture()`, invalidates the overlay, and returns whether either aborted something.
- **Listeners** (subscribed in the constructor; the registry is built before any other `mode` subscriber, [Editor composition](#editor-composition)): `mode` → `cancel()`, then, when the active tool is no longer allowed, `activate('select')`, or with Select not registered, `deactivate()` and `active = null` (emits `tool`); `history` → when a press is open but the state reports no gesture (Undo closed it, or a reset dropped it), mark the press cancelled and call `tool.cancel()`; model `reset` → `cancel()`.
- **`bindView(view: ToolView) → () => void`:** connects the viewport; until bound and after unbinding, `hitTest` returns `[]` and the other view calls do nothing. The registry calls `view.setCursor` with `override ?? tool.cursor`, or `'default'` with no active tool, on binding, on activation (which clears the override) and on `ctx.setCursor`.
- **`drawOverlay(g)`:** `g.clear()`, then the active tool's `drawOverlay(g)`. The viewport calls it at most once per frame, after `invalidateOverlay()`, a `camera` event or a `tool` event.
- `on/off('tool')`.

**Input routing** (`js/viewport/input.js`, UI). Navigation (pan, zoom) is handled first and never reaches tools; `F` and `Home` are the `frame-selection` and `frame-all` actions.
- Left presses (without Space held) and right presses on the host become `tools.pointer({ type: 'down', … })`; a left press captures the pointer. Moves over the host, or captured, become `move`; releases become `up`. `clicks` is 2 for a press within `DOUBLE_CLICK_TIME` and `DRAG_THRESHOLD` of the previous click's press, else 1. The host's `contextmenu` is always prevented.
- `pointercancel`, `lostpointercapture` and window `blur` during a left press call `tools.cancel()`.
- After a pan or zoom step during a left press, and on a `keydown`/`keyup` of Shift, Control, Alt or Meta on the host while a press is open or the pointer is over the host, the last pointer position is re-sent as a `move` with the current modifiers. The Alt `keyup` is prevented so the browser menu bar does not take focus ([`DESIGN.md` §12](../DESIGN.md#12-open-items--to-verify)).
- Hover: idle moves (no button, no navigation) call `onHover(screen)`, at most once per frame; leaving the host, any press and navigation call `onHover(null)`.

**Selection display and hit testing** are not tools: hover, selection and invalid outlines come from `js/viewport/gizmos.js`; what a click selects is the Select tool's job (#13), using `ctx.hitTest`.

### Actions and hotkeys

- **`ActionRegistry`** `js/actions.js`: `register(id, ActionSpec)` with `ActionSpec { run(), isEnabled?() → boolean (default true), reason?() → string | null (default null), repeatable?: boolean }`; registering an id twice, an empty id or a spec without `run` throws. `has(id)`; `isEnabled(id)` (`false` when not registered); `reason(id)` → `'not available yet'` when not registered, else the spec's `reason()` while disabled, else `null`; `isRepeatable(id)` (`false` when not registered or `repeatable` is not `true`), read by `dispatchKey`; `run(id) → boolean`, which runs only a registered, enabled action and says whether it ran. `repeatable` is set for `undo`, `redo` and `next-frame` ([`DESIGN.md` §5.9](../DESIGN.md#59-hotkeys-defaults)). Ids reuse the header ids (`new`, `load`, `save`, `undo`, `redo`, `play`, `pause`, `next-frame`, `stop`, `window`, `settings`) and add `toggle-play`, `delete`, `group`, `ungroup`, `duplicate`, `key-selected`, `frame-selection`, `frame-all`, `sprite-edit`, `escape`, `tool:<id>`, `panel:<id>` (toggle a panel) and `reset-layout`. DOM-free actions are registered by `js/editor.js`; actions that need the DOM (`window`, `panel:<id>`, `reset-layout`, later file pickers and confirmations) by `js/main.js` ([Editor boot](#editor-boot)). The header and hotkeys both call `run`; the header refreshes `aria-disabled` and its tooltip from `isEnabled` and `reason` on `history`, `mode` and `selection` events.
- **No commands during a gesture:** every action that executes a command (`delete`, `group`, `ungroup`, `duplicate`, `key-selected`, …; not `undo`, `redo`, `escape`) reports `isEnabled() === false` with `reason` `null` while `history.inGesture`. Only the gesture owner (the tool registry, an inspector scrub) executes commands inside its gesture. This keeps a key pressed mid-drag out of the drag's undo step and rules out the cancellation re-entrancy described in [Commands and undo](#commands-and-undo). The header is not refreshed on gesture start, which is harmless: the pointer is captured by the drag, and `run` re-checks `isEnabled`.
- **`HOTKEYS`** `js/hotkeys.js`: frozen `Hotkey { keys, action }` rows for §5.9 in table order (`{ keys: 'Ctrl+Shift+Z', action: 'redo' }`, `{ keys: 'Ctrl+Y', action: 'redo' }`, `{ keys: 'Space', action: 'toggle-play' }`, …); #12 puts first one `tool:<id>` row per `TOOL_SPECS` entry, built from its `hotkey` (`{ keys: 'V', action: 'tool:select' }`, …), for every tool whether registered or not. `keys` is `[Ctrl+][Shift+][Alt+]<key>`, where `<key>` is an upper-case letter, a digit, `.`, `Space`, `Del`, `Esc` or `Home`. The header's shortcut hints must equal this table (tested): for each header action with a hint, its rows joined with `' / '` in table order, `play` and `pause` reading the `toggle-play` rows.
- **`matchHotkey(event) → ActionId | null`**: `Meta` counts as `Ctrl`; `event.key` is compared case-insensitively for letters (`Del` = `Delete`, `Esc` = `Escape`, `Space` = `' '`); Ctrl, Shift and Alt must match the row exactly, so `Ctrl+Z` never matches with Shift held.
- **`dispatchKey(event, { tools, actions, viewportFocused }) → boolean`** (`tools` may be `null` until #12) order:
  1. ignore if `event.defaultPrevented` (a focused widget handled the key) or the target is a text field (`input` other than checkbox, radio, range, button types), `textarea`, `select` or `isContentEditable`;
  2. if the viewport has focus, `tools.key(e)`; stop if consumed;
  3. `matchHotkey(e)`; on a match, `preventDefault` (even when the action is disabled, so the browser's shortcut never fires), then, unless `event.repeat` and `actions.isRepeatable(id)` is `false`, `actions.run(id)`. Space only matches when `viewportFocused` or the target is the page `body`, and the viewport turns Space into pan-or-toggle ([`DESIGN.md` §5.9](../DESIGN.md#59-hotkeys-defaults)).
  
  It returns `true` when the key was consumed (by a tool or a match). It reads only properties of `event` and its target; it never touches `document`.
- `escape` runs `tools.cancel()`, and clears the selection when nothing was cancelled (until #12: `history.cancelGesture()`, see [Editor composition](#editor-composition)). `tool:<id>` runs `tools.activate(id)`; a switch during a drag cancels the drag ([Tools](#tools)).

### Modes

`js/modes.js`: `new Modes(model)` holds `mode` (`'edit'` at start), `clip` (open clip uid or `null`), `playhead` (s, `0` at start) and the state before Simulate. Behavior: [`DESIGN.md` §5.1](../DESIGN.md#51-editor-modes).

- **`openClip(uid | null)`**: a clip uid enters Animate with that clip, `null` enters Edit (`clip = null`, `playhead = 0`). Opening a different clip sets `playhead = 0`; opening the open clip again is a no-op. Throws in Simulate (`clip.open` is refused) and for a uid that is not a clip.
- **`setPlayhead(t)`**: clamps to `[0, length]` of the open clip, and to `[0, 0]` without one (Simulate started from Edit), so the playhead stays `0` there. Allowed in Animate and Simulate (the playback driver, #54), throws in Edit and for a non-finite `t`. Snapping is the timeline's job.
- **`startSimulate()`** from Edit or Animate stores `{ mode, clip, playhead }` and enters Simulate, keeping `clip`; **`stopSimulate()`** restores the stored state. Each throws when called in the wrong mode. In #10 nothing calls them yet (Play/Stop come with #54); they are tested directly.
- **Model listeners:** a `remove` change of the open clip closes it: outside Simulate as `openClip(null)`; in Simulate it sets `clip = null`, keeps the playhead, and stores Edit (`clip = null`, `playhead = 0`) as the state to restore, so Stop returns to Edit at 0; a `set` of the open clip's `length` re-clamps the playhead; `reset` returns to Edit with `clip = null`, `playhead = 0` and drops the stored state, from any mode.
- **Events:** `mode` when `mode` or `clip` changes, then `playhead` when the playhead changed in the same call; `playhead` alone for `setPlayhead` and re-clamps. Nothing is emitted when nothing changed.
- **`can(capability) → boolean`** reads `MODE_POLICY`, a frozen `{ [Capability]: { edit, animate, simulate } }` of booleans; an unknown capability throws. Its rows map one-to-one to the policy table in [`DESIGN.md` §5.1](../DESIGN.md#51-editor-modes) (tested against it):

### Dock layout

`js/panels/layout.js` holds the layout as data and owns every layout rule; `js/panels/dock.js` renders it and turns pointer and keyboard input into layout operations, without re-deriving those rules. Behavior and sizes: [`DESIGN.md` §5.2](../DESIGN.md#52-panels).

```
PanelId     'hierarchy' | 'assets' | 'problems' | 'inspector' | 'timeline'
PanelSpec   { title, group, edge: side, size, min: { width, height } }
LayoutNode  SplitNode | StackNode | { type: 'viewport' }
SplitNode   { type: 'split', dir: 'row' | 'column', children: LayoutNode[], sizes: (number | null)[] }
StackNode   { type: 'stack', id: string, panels: PanelId[], active: PanelId }
Layout      { version: 2, tree: LayoutNode, closed: { [PanelId]: { stackId: string, index: number } },
              timelineFolded: boolean }
TimelineFold { stackId: string, folded: boolean } | null
Drop        { kind: 'tab', stackId, index } | { kind: 'split', stackId, side } | { kind: 'edge', side }
            side = 'left' | 'right' | 'top' | 'bottom'; a split with stackId 'viewport' splits the viewport node
Rect        { x, y, width, height }   CSS px, relative to the workspace content box
Gutter      { path: number[], index, controlled, dir, rect: Rect, value, min, max }
            px; the split at `path` (child indexes from the root), between children index and index + 1;
            `controlled` is the child it resizes, `value` that child's current size, [min, max] its bounds
LayoutRects { stacks: Map<stackId, Rect>, viewport: Rect, gutters: Gutter[], width, height, tabs?: Map<stackId, Rect[]> }
```

- **Viewport** is a node, not a `PanelId`; it appears exactly once and never inside a stack. The Tools overlay is not part of the layout ([`DESIGN.md` §5.5](../DESIGN.md#55-tools)). `PANELS` maps each `PanelId` to `{ title, group, edge, size, min: { width, height } }` from the §5.2 table, in Window menu order; `group` is the default stack (`hap` for Hierarchy, Assets, Problems). `TAB_BAR_HEIGHT` is 28. `defaultLayout(workspace)` is `column[ row[ viewport, column[ hap, inspector ] ], timeline ]` with `timelineFolded: true`; it takes the workspace size because the Hierarchy stack starts at half the right column's height, measured with the Timeline folded.
- **Sizes** are px along the split axis. Exactly one child per split has `null` (fill): the one containing the viewport, otherwise the last. Every operation re-derives it. A gutter controls child `index` when the fill comes after it, else child `index + 1`; `resizeSplit` and the dock both use `Gutter.controlled` for this. `computeRects(layout, workspace)` gives fixed children their size, the fill the rest; if the fill falls below its minimum, the others shrink in proportion to their size above their own minimum, and if the minimums still do not fit, the content size exceeds the workspace (it scrolls). Shrinking only affects the rects, never the stored sizes, with one exception: `resizeSplit` first stores the on-screen size of every shrunk fixed sibling (the folded Timeline and the fill child excepted), so the dragged edge follows the request and siblings do not grow back later. Minimum sizes of splits are derived from their children plus 4 px gutters; a stack's minimum is the largest minimum of its panels. It returns a `LayoutRects` without `tabs`.
- **Timeline fold.** `timelineFold(layout)` returns `null` unless the Timeline is **foldable**: open, the active panel of its stack, and that stack a fixed (non-fill) child of a `column` split. Otherwise it returns its `stackId` and `folded = layout.timelineFolded`. The flag is kept when the Timeline is not foldable and only takes effect while it is. For a folded stack `computeRects` uses `TAB_BAR_HEIGHT` as its height and as its minimum height, with no slack to shrink; its stored size is untouched; the gutter whose `controlled` child it is is left out of `gutters` (its 4 px space stays). `setTimelineFolded(layout, folded)` sets the flag and throws when `timelineFold` is `null`. These operations clear the flag (expand): `activatePanel` of any panel of the Timeline's stack, including its already active tab; `openPanel` of the Timeline, or of a panel that lands in the Timeline's stack; `movePanel` of the Timeline, or a `tab` drop into its stack. `closePanel` and `resizeSplit` keep it; `resizeSplit` on the folded stack's gutter throws, as there is none.
- **Normalize** (after every operation): drop empty stacks; a split with one child becomes that child; a split nested in a split of the same `dir` is flattened (its fill takes the slot it occupied minus the fixed siblings); space freed by a removed child goes to its previous sibling, else the next; fill is re-derived; `active` must be one of `panels`, else the first; `timelineFolded` is kept.
- **Operations** are pure, return a new deep-frozen `Layout` and throw on an id that is unknown or in the wrong state. `activatePanel` changes the active tab; `closePanel` records `{ stackId, index }` in `closed` and activates the neighbour tab; `openPanel` applies the reopen rule and activates the panel; `movePanel` applies a `Drop` that `canDrop` accepts (an existing stack or the viewport; a tab index within `0..panels.length`; not a `tab` drop on the viewport; not the panel's own stack when it is its only tab) and activates the panel; `resizeSplit(layout, path, index, value, workspace)` stores the on-screen sizes of the split's shrunk siblings, then sets the controlled child, clamped to `[min, max]` and rounded to whole px. New stacks get id `s<n>` above every stack id in `tree` **and** in `closed`, so a closed panel never reopens into an unrelated stack that reused its old id. Edge splits give the moved panel half the target, edge docks the panel's default size capped at 1/3 of the workspace, both respecting minimums. Folding follows the rules above.
- **`dropAt(layout, rects, point, panelId, workspace) → { drop, preview: Rect, caret?: Rect } | null`**, `point` in content coordinates, first match wins:
  1. **Tab bars** (the top 28 px of any stack, a folded stack entirely): a `tab` drop at the insertion index from `rects.tabs` (measured by the caller; the end when absent), previewed as a 2 px caret in `preview`. Tab bars win over edge strips.
  2. **Edge strips** of 16 px along the content box, nearest edge wins: an `edge` drop previewed with the size `movePanel` will give (default size capped at 1/3 of `workspace`).
  3. **Stack edge zones** of 25 % of the stack dimension clamped to 24–80 px, nearest edge wins: a `split` drop previewed as the half the panel will take.
  4. **Stack center:** a `tab` drop at the end, with `preview` the stack rect and `caret` the 2 px insertion caret after its last tab.
  5. **Viewport edge zones** (same size rule): a `split` drop with `stackId: 'viewport'`.

  The viewport center, gutters, points outside the content and drops refused by `canDrop` give `null`.
- **Stored layout:** `LAYOUT_VERSION` is 2 (Tools left the dock and `timelineFolded` was added). Version 1 records are not migrated: no release shipped them, and they are ignored with the usual warning. `validateLayout(value) → string | null` returns the first reason it is invalid: not an object, `version !== 2`, `timelineFolded` not a boolean, malformed node or split `dir`, a tree deeper than 32 levels, a split without children, `sizes` not matching `children` in length, not exactly one `null`, a size that is not finite, not > 0 or above 100000 px, a stack id that is empty, `'viewport'` or repeated, `panels` not an array, an empty stack, an unknown or repeated panel id across `tree` and `closed`, `active` not in its stack, viewport not exactly once, `closed` not an object, or a `closed` entry without a string `stackId` and an integer `index ≥ 0`. `restoreLayout(value, workspace) → { layout, warning }` returns the default layout and `warning: 'Stored layout ignored: <reason>'` when invalid, and adds every panel missing from both `tree` and `closed` by the reopen rule.
- **Dock:** reads `loadLayout()` once on creation (`parse` → warning, `missing`/`unavailable` → default without warning; an exception from `restoreLayout` → warning and default), logs a warning with `console.warn`, and calls `saveLayout` after a drop, a resize end, a tab change, a close or a reopen; keyboard resizing saves 500 ms after the last key. `reset()` calls `clearLayout()` and applies `defaultLayout` without saving. It emits `layout` with `{ layout }` after every change, including each pointer move of a resize and its Esc revert. It re-renders stacks on structural changes and only re-places rects on resizes and on workspace size changes (`ResizeObserver`), which never change the layout; every `place()` also keeps each stack's active tab visible.
  - **DOM order** of the content children follows the layout tree depth-first (child, gutter, child, …; the viewport panel in its slot; the drop preview last), and is re-applied on structural changes without detaching the focused element when it stays (move siblings around it), so Tab order follows the layout and focus survives. When a re-render must recreate a focused tab, it refocuses the tab of the same panel, as it does today.
  - **Tab bars:** the tab list scrolls; a vertical wheel over an overflowing tab list scrolls it horizontally (`preventDefault` only while it can still scroll in that direction); a 12 px fade is shown on each clipped edge (classes toggled from `scrollLeft`, `clientWidth`, `scrollWidth` on scroll and on `place()`).
  - **Fold button** (only when `timelineFold(layout)` is not `null`): a 24 × 24 px button after the tab list, outside its scroll area, in the Timeline's stack; ▾ expanded, ▸ folded; `aria-expanded`, `aria-controls="panel-timeline"`, accessible name "Timeline content", tooltip "Fold" / "Expand"; a normal Tab stop. A click, or a double click on the empty part of that tab bar, calls `setTimelineFolded`. A click on a tab of the folded stack calls `activatePanel` even when it is already active. While folded, the panel element is `hidden`; if focus was inside it, focus moves to the fold button. Folding saves the layout immediately.
  - **Gutters:** `aria-label` is "*name* width" for `row` splits and "*name* height" for `column` splits, where *name* is that of `Gutter.controlled`: "Viewport" for an area holding the viewport, else the active tab of its first stack in tree order. `aria-controls` points to that area's element.
  - `windowItems()` returns the §5.3 Window menu items: one checkbox per panel in `PANELS` order preceded by Viewport (checked and disabled), a separator, then `reset-layout`. `close(id)` repairs focus when the closed panel, its tab or its close button had it: the new active tab of its stack, else the viewport host. Its tab lists and separators, like `js/menu.js`, call `preventDefault` on the keys they handle ([Actions and hotkeys](#actions-and-hotkeys)). Layout operations never go through history.

### Emitter

`lib/emitter.js`, used by the editor core and by `RagInstance` (#47).

```
class Emitter {
  on(type: string, fn: (payload) => void): () => void   returns an unsubscribe function
  off(type: string, fn): void
  emit(type: string, payload?): void
  clear(): void                                          removes every listener
}
```

- Listeners run synchronously, in subscription order, with one payload argument. A function is registered at most once per type.
- `emit` iterates a copy of the listener list: listeners added or removed during an emit take effect on the next one.
- Every listener runs even if one throws; the first error is rethrown after the last listener.
- No wildcard types, no `once`, no async.

### Schema

`lib/schema.js` is the single code source of field types, defaults, ranges, enums, units, editor-only flags and canonical order; [schema.md](schema.md) documents it. It lives in `lib/` because `lib/validate.js` and `lib/serialize.js` need it and `lib/` cannot import `js/`. Model defaults, validation, the serializer and the inspector never redeclare a default, range or key order.

## Data flow

1. **Authoring:** UI action → command → `history.execute` → model ops → one `change` event → views update their own entries (scene, hierarchy, inspector, timeline, Problems after a debounced `validate(toJson(model))`).
2. **Save:** `toJson(model)` → `validate` (blocked on errors) → `serialize` → `.rag.json` (+ sprite files). **Load:** parse JSON → `migrate` → `validate` → `loadJson` → `reset`.
3. **Animate mode:** model clips → `lib/evaluate.js` at the playhead → FK pose (`scene.setPose`) and sprite channels.
4. **Simulate mode / runtime:** `toJson(model)` → `RagImporter.parse` → spawn in a LiquidFun world → each step:

```
rag.update(dt)    advance clips, fire events, resolve channels + overrides, write motors and textures
world.Step(dt)    LiquidFun integrates
rag.sync()        body transforms → PIXI sprites
```

## Conformance

A change conforms when its modules, exports and imports match this document.

- **Automated (#66):** `tests/architecture.test.js` enforces these rules on every `.js` file under `js/`, `lib/`, `demo/` and `tests/`, with the layer classification parsed from this document by `tests/helpers/architecture.js` (the Core row of the layers table, the `Pure` line of the [Components](#components) diagram, the `js/` modules in the `tests/` dependency row):
  - **Imports** follow the [Dependency rules](#dependency-rules) and layers (static scan of imports, re-exports, dynamic `import()` and `require()` with a literal specifier; non-relative specifiers such as URLs, bare packages and `node:*` are rejected in `js/`, `lib/` and `demo/`; `tests/` may use `node:*` only). In `tests/`, `vendor/liquidfun.js` may be loaded only by `tests/liquidfun-*.test.js`, and no test may import `demo/` or `vendor/pixi.min.js`. Panel content modules (any `js/panels/*.js` other than the dock modules) may import nothing from `js/panels/`: not each other, and neither `js/panels/layout.js` nor `js/panels/dock.js`, even though `layout.js` is core.
  - **Pure modules** (the `lib/` pure set and the `js/` core) reference none of the globals `document`, `window`, `PIXI`, `Box2D` or any `b2*` name. Property accesses and object keys do not count. The scan is complemented by the load check below.
  - **Main-only globals:** among `js/` modules only `js/main.js` references the `PIXI` and `Box2D` globals; every other module receives them as parameters. Same reference rules as the pure-module check; additionally a name bound by a function parameter (`createViewport(PIXI, host)`) or a `const`/`let`/`var` declaration is not the global within that binding's scope.
  - **Model mutation calls:** `applyOps` and `batch` are called only by `js/commands/history.js`, and `reset` only by `js/model/io.js`. A call is detected only when its receiver is an identifier ending in `model` (`model.reset(…)`, `this.model.batch(…)`, `editor.model?.applyOps(…)`); a call through an alias (`const m = editor.model; m.reset(…)`) or a destructured method is not detected and is left to review. `tests/` is exempt.
  - **Load check (#106):** every pure module present on disk (the `lib/` pure set and the `js/` core; planned modules not on disk are skipped) is imported dynamically under `node --test` with `document`, `window`, `PIXI` and `Box2D` undefined on `globalThis`, before and after loading. A module that touches a global at load time, through an alias the scan cannot see, fails the test with its path and the error. Only load-time access is caught: a global used inside a function that the load does not call is left to the scan and to review.
  - **Comments:** only `/** … */` JSDoc blocks.

  Not automated, checked in review: exports matching the module map, and that modules which need `PIXI`/`Box2D` are actually handed them as parameters.
- **Pull requests:** the PR template has a conformance item. A PR that adds, removes, renames or changes the responsibility or imports of a module updates the module map on the same branch, through the architect, and is reviewed by the architect before merge.
- **Disagreement:** if code needs a module or import this document does not allow, stop and ask the architect; do not merge a deviation.
