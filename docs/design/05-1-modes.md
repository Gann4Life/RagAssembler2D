# 5.1 Editor modes

| Mode | Entered by | Viewport shows | Edits affect |
|---|---|---|---|
| **Edit** | Mode switch *Edit* ([§5.3](05-3-header.md#53-header)), or "(rest pose)" in the Timeline clip selector | Rest pose | Rest pose / object properties |
| **Animate** | Mode switch *Animate*, or choosing a clip in the Timeline clip selector, or New clip | The clip simulation at the playhead with every tool (Animate view, below), plus the ghosts; sprites of the evaluated clip | Keys of the open clip |
| **Simulate** | Mode switch *Simulate*, or Play in Edit mode | Live physics through RagImporter | Nothing (read-only). Stop returns to the previous mode |

The header mode switch always shows the current mode, also while the Timeline is folded or closed; the Timeline clip selector shows the same state ("(rest pose)" in Edit mode, the open clip otherwise). Modes change only through these controls, Play in Edit mode and Stop in Simulate ([§5](05-editor.md#visible-controls-and-feedback)).

**Animating loop.** Animate is where clips are made and watched: the user plays or scrubs the clip and sees its physics, grabs what looks wrong with Pose at the moment it shows (a press while playing pauses there), and plays on from that time. The user finds what to correct in what physics shows and corrects the intent: the main figure is the clip simulation with every tool, a Pose press switches it to the keyed pose at that time (contacts and lag removed, [§5.5](05-5-tools.md#55-tools)), and nothing in the loop jumps to the rest pose or needs Stop. Play, Pause, Stop and scrubbing never change the mode or the tool. Simulate is not part of this loop: it is the live physics test (rest pose from Edit, the open clip from Animate) with the inputs a precomputed run cannot have: procedural preview, triggering clips on the running instance, contacts.

**FK preview:** the **FK pose** places bodies by forward kinematics from the evaluated clip. In Animate mode the viewport shows it only when the clip simulation is not available (below):
- `rootBody` is rotated by the evaluated root `bodyAngle` ([§4.2](04-animation-model.md#42-channels)) around its **center of mass** in the rest pose (`bodyMassData`, root-local; the body origin when its mass is 0), which stays fixed: a free body turned by a pure torque, as the balance controller does at runtime ([§3.2](03-physics-drive-model.md#32-balance-controller-rootbody-orientation)). At `bodyAngle = 0` it is at its rest transform;
- each child is rotated around its joint anchor by the evaluated `angle`, carried by its parent's FK transform, so the whole ragdoll follows `rootBody`. The angle is bodyB relative to bodyA, so through a reversed joint ([§2.4](02-object-model.md#24-joints)) the child turns by −`angle`.

Multiplier channels don't move anything. They are shown as the fill of the joint gizmo (grey 0 % → saturated 100 %). Sprite channels swap images live.

**Clip simulation.** In Animate mode the editor keeps a physics run of the open clip: the same world as Simulate (gravity, ground, motors following the open clip alone, without the preview stack or procedural inputs) stepped at the fixed 60 Hz step. The ground's top is always at the lowest point of the rest pose, and a posed spawn is moved vertically so that its lowest point touches it, so every run (and Simulate) shares one ground in root-local coordinates. How it starts and how long it runs depend on the clip's `loop` (owner decision):
- **Start (every clip):** spawned in the **clip's own pose** at clip time 0 (RagImporter's `pose` spawn option), so keys at time 0 show at once; a clip without keys starts at rest (channel defaults). This is an editor preview rule only: at runtime `play(key)` on a spawned ragdoll never respawns or teleports, it blends from the current pose ([§4](04-animation-model.md), [§7](07-ragimporter.md)), and spawning in a clip pose stays the explicit `spawn({ pose })` opt-in.
- **Non-looping clip:** run to `length`.
- **Looping clip:** spawned in the clip's **pose at time 0** (RagImporter's posed spawn, [§7.2](07-ragimporter.md#72-spawn-and-flipx), the editor using the same option a host uses) and run **continuously** through its cycles: at each wrap the clip goes back to time 0 while the bodies keep their state, as at runtime, and the targets stay continuous through the wrap segment ([§4.3](04-animation-model.md#43-keys-and-interpolation)), which also gives the pose at time 0 when a track's first key is later. **Cycle** *c* (1, 2, …) covers run time (*c* − 1) × `length` to *c* × `length`. The run computes cycles in order up to its **horizon**: the later of cycle 2 and the cycle after the playhead's, never past the **cycle limit** of 8 (tuning in [§12](12-open-items.md#12-open-items--to-verify)), so the second cycle, which shows what the wrap does, is always available.

The playhead is a clip time *t* plus, for a looping clip, its cycle (the **playhead cycle**, 1 when a clip opens). The run is deterministic, so the pose at (cycle, *t*) is the pose of the step at that run time, whatever the order in which times are viewed.
- **Computed in the background**, within a per-frame budget, from the start forward, keeping every step's body transforms, so scrubbing back reads the stored step instead of simulating again. It starts when Animate opens a clip and again 250 ms after the last committed document change (the end of an undo step: a Pose release, an inspector commit, Undo, Redo, …; never during a drag), and it extends when the playhead cycle moves the horizon. The previous run is kept until the new one reaches its horizon (no flicker on edits). It never changes the document. Its progress shows under the Timeline ruler ([§5.8](05-8-animation-timeline.md#58-animation-timeline)).
- **Pose at a time** *t* (in the playhead cycle for a looping clip): the current run's step there once the run has reached it; else the previous run's step there when that run reached it; else, for the main figure, the latest step the current run reached (shown until it catches up, also while playing), and for a ghost, none.
- **Dropped** on opening another clip and on leaving Animate.
- **Not available** when the document cannot be simulated (validation errors, [§6.4](06-file-format.md#64-validation)): Animate then shows the FK pose with every tool, playing included (Play plays the FK pose), and no ghosts or progress bar. The status line shows "Clip simulation: fix the errors in Problems" on entering Animate with errors and when the first error appears in Animate ([§5](05-editor.md#visible-controls-and-feedback)); the run starts again by the usual rule once the errors are fixed. A run that fails for any other reason (a native error at spawn) leaves it not available the same way, and the status line shows "Clip simulation failed: *message*" instead.

**Animate view.** The main figure shows the clip simulation at the playhead (pose at a time, above), playing, paused or after a scrub, whatever tool is active: choosing a tool never changes what is displayed. The rest pose is never shown in Animate other than as the clip simulation's own state (a clip without keys at time 0, above), and the FK pose only when the clip simulation is not available. Two states stand in for the clip simulation for a while, and one rule joins them to it:
- **Pose drag:** the drag's simulated bodies, started from the keyed pose placed on the grabbed displayed body, with no gravity and no ground, `rootBody` free like every body ([§5.5](05-5-tools.md#55-tools)). Nothing in Animate pins or drives `rootBody` kinematically: the clip simulation moves it only through joints, contacts and the balance controller.
- **Posed hold:** after every Pose release, the released bodies, held at the playhead, until the clip simulation is **up to date at the playhead**: a run started after the last committed document change has reached the playhead's step. When the release committed nothing (nothing to key, a click) and the current run already reached the playhead, it is up to date at once. The hold then ends with a handover. It also ends, with no handover, when the playhead is moved by a scrub, the cycle control ([§5.8](05-8-animation-timeline.md#58-animation-timeline)), Next frame or Stop, when another clip opens and on leaving Animate. Play during the hold starts playback (the button shows Pause) with the playhead waiting at its time until the hold ends with its handover, then moving on, so playback continues from the corrected frame with the run that includes the correction.
- **Handover:** whenever the main figure changes source without the playhead being moved by the user (posed hold, a previous run's step or the latest step reached, to the current run's step), it blends over 150 ms: each body's position and continuous angle go linearly, with a smoothstep in time, from the pose shown when the handover starts to the target, which keeps following the playhead while playing. Display only: it never changes the document or the run. A scrub, the cycle control, Next frame or Stop shows the new time at once.

Sprites follow the evaluated clip at the playhead in every case.

**Ghosts (onion skins).** In Animate mode, with every tool and while the Onion skins toggle is on ([§5.8](05-8-animation-timeline.md#58-animation-timeline)), the clip simulation is also drawn at the **key times** of the open clip nearest the playhead: of the distinct times in `[0, length]` that hold a key in any of its tracks (events are not keys), only the nearest one before the playhead and the nearest one after it get a ghost, so at most two are drawn. The neighbors are searched as if the clip did not loop: never across the wrap, so with the playhead before the first key time there is no ghost behind, and after the last one no ghost ahead, also for a looping clip. A key time is skipped while it maps to the same simulation step as the playhead. A ghost is **green** for the key time after the playhead and **red** for the one before it, so the colors flip as the playhead passes. Ghosts read the same run as the main figure (no run of their own, on the same rest-pose ground), in the playhead cycle, so a ghost is exactly the main figure the playhead will show (or showed) at its key time. A ghost shows the pose at a time (above) at its key time: the current run once it reached that time, else the previous run, else no ghost; the posed hold and the handover concern the main figure only. Ghosts draw shapes only (no sprites, gizmos, names, joints or overlays) and are never hit, hovered or selected ([§5.4](05-4-viewport.md#54-viewport), Ghosts). They follow the keys at once (a removed key time loses its ghost), and their poses follow the run, so in this version they update after a committed edit, not during a Pose drag ([§12](12-open-items.md#12-open-items--to-verify), post-MVP).

**Displayed pose.** Tools, gizmos and hit testing in Animate mode use the main figure of the Animate view; ghosts are never part of it.

**Mode policy.** What each mode allows (✓) or disables (—). Disabled controls stay visible, use `aria-disabled` and give the mode reason ([§5](05-editor.md#visible-controls-and-feedback)); disabled inspector fields are read-only.

| Animation edits: clip properties, tracks, keys, events, key buttons ◆, Key selected (K), Pose → keys | — | ✓ | — |
| Asset import | ✓ | ✓ | — |
| Asset delete | ✓ | — | — |
| Clip selector, New clip | ✓ | ✓ | — |
| Rename clip | ✓ | ✓ | — |
| Clamp keys to limits (all clips, [§5.6](05-6-hierarchy-assets-problems.md#56-hierarchy-assets-and-problems-panels)) | ✓ | ✓ | — |
| Mode switch | ✓ | ✓ | ✓ (below) |
| Scrub | — | ✓ | — |
| Preview stack | — | ✓ | ✓ |
| Procedural preview | — | — | ✓ |
| New, Load, Save; Undo, Redo | ✓ | ✓ | — |
| Play (Edit: enters Simulate; Animate: plays the clip in Animate; Simulate: resumes) | ✓ | ✓ | ✓ |

| Editor settings (grid, snapping, display, pivot), panels, navigation | ✓ | ✓ | ✓ |

- In Animate mode, inspector fields that are not animatable are shown read-only, and animatable ones show the evaluated value with their key button. **Pose is the animation tool.** Select only selects in Animate and Simulate mode: no gizmo, and every drag draws a selection box ([§5.5](05-5-tools.md#55-tools)); it never writes keys.
- **Mode changes and tools.** Changing mode cancels the tool operation in progress (as Esc) and never changes the active tool. When the new mode disables the active tool, it stays active and pressed, shown disabled with the mode reason, and a viewport press with it changes nothing and shows the reason in the status line ([§5](05-editor.md#visible-controls-and-feedback)); the user chooses another tool or another mode.
- **Playhead and open clip.** Opening a different clip puts the playhead at 0 (cycle 1); the playhead always stays within `[0, length]` of the open clip, also when `length` changes, and its cycle within 1 to the cycle limit. Turning `loop` on or off, like any edit, restarts the run; the playhead cycle becomes 1 when `loop` turns off. The editor remembers the **last opened clip** of the session (forgotten by New and Load) for the mode switch.
  - When the open clip stops existing (deleted, or its creation undone) the editor returns to Edit mode and the status line shows "Clip *name* removed: Edit mode" (the clip's name, or its key when the name is empty).
  - New and Load return to Edit mode with the playhead at 0.
- **Playback in Animate** ([§5.3](05-3-header.md#53-header)). Play moves the playhead in real time (clip time, so at the clip's `speed`) from where it is, or, for a non-looping clip, from 0 when it is at `length`; the view shows the clip simulation (Animate view). At `length` a non-looping clip pauses. A looping clip **wraps** to 0 in the next cycle and goes on, so the figure continues from the state the previous cycle left (continuous run, above); at the end of the cycle limit it pauses at `length` and the status line shows "Clip simulation: cycle limit 8 reached". Play at that point starts again from cycle 1, time 0. Pause keeps the playhead where it is and the figure as shown; it never drops or restarts the clip simulation, so Play resumes from the playhead on the same run, or on the recomputed one after an edit. A Pose press while playing pauses too ([§5.5](05-5-tools.md#55-tools)). Next frame pauses and moves the playhead one fixed step (1/60 s × `speed`): a non-looping clip stops at `length`, and a looping clip at `length` wraps to 0 plus one step in the next cycle, and stops at `length` of the cycle limit. Stop pauses and puts the playhead back where the last Play started, cycle included. A scrub while playing pauses playback and moves the playhead. Opening another clip, leaving Animate, New and Load stop playback. Document edits during playback (Undo included) do not stop it.
- **Simulate** is a live run: from Edit mode of the rest pose with no clip, from Animate of the open clip from 0, spawned as the clip simulation spawns (the clip's pose at time 0, looping or not) and running on with no cycle limit. Stop, or the mode switch's *Edit* or *Animate* segment, ends it and restores the mode, clip and playhead that were active before it; *Edit* or *Animate* then enters that mode if it is not the restored one ([§5.3](05-3-header.md#53-header)).
