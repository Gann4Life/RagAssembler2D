# 5.6 Hierarchy, Assets and Problems panels
Default location ([§5.2](05-2-panels.md#52-panels)): right top, as tabs of one stack.

**Hierarchy**
- **Layout:** a toolbar row with the search field, an **Add** menu button and, right of it, an icon-only **Delete** button (a trash can), above the tree. Tab order inside the panel: search field, Add, Delete, then the tree (one Tab stop).
- **Tree:** every body, shape and joint of the document has exactly one row, and the tree follows every change at once (creation by tools or Add, deletion, undo, redo, inspector edits, New, Load).
  - The root row comes first and is the only top-level row.
  - Below it is the joint tree from `rootBody`, in the order body → joint → child body: a body row holds its shapes (in fixture order), then the joints that reach its child bodies (in `joints` order), and each such joint row holds its child body. Which joint reaches a body is the spanning tree of [§2.4](02-object-model.md#24-joints) (fewest joints to `rootBody`, `joints` order first).
  - Every body shows its shapes, also a body with a single shape, so a shape selected in the viewport always has a row.
  - A joint that closes a loop (a loop joint, [§2.4](02-object-model.md#24-joints)) is a leaf row under its `bodyA`, marked with a muted "loop" badge followed by a muted "→ *bodyB*" (the name of the body it closes the loop to, or its id when the name is empty).
  - Bodies not connected to `rootBody` are listed under an **Unlinked** group row: a warning triangle in the warning color and the muted label "Unlinked". Each unlinked part is its own joint tree with the same rules, rooted at its body that comes first in `bodies`, in that order. Joints that do not connect two different existing bodies (an unassigned joint from *Add joint*, or a broken reference) follow as leaf rows of the group, marked with an "unassigned" badge in the error color. The group row is not an object: it can be focused, expanded and collapsed (also by double-clicking it), but not selected, and it exists only while it has rows.
  - A row shows an icon of its kind (root, body, circle, box, polygon, joint) and the object's name, or its id when the name is empty. Long names are cut with an ellipsis; badges are never cut. Shapes with a sprite show its thumbnail.
  - Rows with children can be expanded and collapsed, and start expanded. The expansion state is per session, kept for each object across changes, not saved and not undoable; New and Load expand everything.
- **Selection** is synchronized both ways with the viewport and the inspector, in every mode ([§5.1](05-1-modes.md#51-editor-modes)):
  - The rows of selected objects are highlighted. When the selection changes outside the Hierarchy (a viewport click or box, a creation tool, the Problems panel), the collapsed ancestors of the newly selected rows are expanded, and the last of them is scrolled into view (as little as needed) and becomes the tree's focused row for the next Tab into it; keyboard focus does not move.
  - Clicking a row selects only that object; SHIFT + click toggles it and CTRL + click removes it (CTRL wins when both are held; Cmd acts as CTRL on macOS), as in the viewport ([§5.5](05-5-tools.md#55-tools)). Clicking a row's expand arrow only expands or collapses it. Clicking the empty area below the rows clears the selection.
  - Double-clicking an object row selects only that object and frames it, as F does ([§5.4](05-4-viewport.md#54-viewport)).
  - A body row selects the body itself: every shape of it is outlined in the viewport ([§5.4](05-4-viewport.md#54-viewport)). This is the only place a body is selected.
- **Keyboard:** the tree is one Tab stop, and the focused row is its roving stop.
  - Up/Down move to the previous/next visible row and Home/End to the first/last, without wrapping. Focus moves select (selection follows focus): the row reached becomes the only selected object; with SHIFT it is added to the selection; with CTRL focus moves and the selection is unchanged. Reaching the Unlinked group row leaves the selection unchanged.
  - Right expands a collapsed row, or moves to the first child of an expanded one; Left collapses an expanded row, or moves to its parent. Moves to a child or parent select like Up/Down.
  - Space, with or without CTRL, toggles the focused row's selection.
  - These keys never trigger global hotkeys ([§5.9](05-9-hotkeys.md#59-hotkeys-defaults)). Every other key is a hotkey as anywhere else (Del, F, Esc, the tool letters): there is no type-ahead, the search field is used instead.
- **Search field** (placeholder "Search"): filters rows by name or id, case-insensitively, as a fuzzy match: the characters of the query, spaces ignored, must appear in the same order, not necessarily together (`knl` matches `knee_l`). While a query is set, the tree shows only the matching rows and their ancestors, starting all expanded; matched characters are highlighted, a row matched by its id shows the id, muted, after its name, and ancestors that do not match are dimmed (muted text). Collapsing during a search is temporary: the normal expansion state returns when the query changes or is cleared. With no match the tree shows "No matches". Esc in a non-empty field clears it. Down in the field moves focus to the first visible row without changing the selection. The filter never changes the selection.
- **Rename** (F2, a global hotkey, [§5.9](05-9-hotkeys.md#59-hotkeys-defaults)): renames the selected object, whatever its type (root, body, shape or joint), when **exactly one** object is selected; with none or several selected, or a sprite asset or clip as the only selection, F2 does nothing. It works wherever focus and the pointer are, except in text fields, which keep their own F2. Edit mode only ([§5.1](05-1-modes.md#51-editor-modes)); unavailable while a drag or scrub is in progress, a rename field is already open, or a confirmation or menu is open.
  - **Where the field opens**, by the pointer's position at the press: over the Hierarchy panel, **inline** in the object's row (an active search is cleared first, the row's collapsed ancestors are expanded and the row is scrolled into view, as little as needed); anywhere else (the viewport, another panel, the header, outside the window), the **rename popup** ([§5.4](05-4-viewport.md#54-viewport)).
  - The field holds the current name, all of it selected, and takes keyboard focus, so tree keys and hotkeys do not act while it is open.
  - Enter, or focus leaving the field (a click elsewhere included), commits; Esc cancels. A new name is stored as typed (empty allowed: rows and labels then show the id) as **one undo step** ("Rename"); an unchanged name records nothing. Enter and Esc return focus to where it was before F2. An undo step being undone, a mode change, New, Load or the deletion of the renamed object while the field is open cancel it. The selection and the id never change.
  - Inside the field, Ctrl+Z and Ctrl+Shift+Z are the field's own text undo and redo ([§5.9](05-9-hotkeys.md#59-hotkeys-defaults)). Any control outside the field (the header's Undo button included) first takes focus, which commits the field, and then acts: Undo then undoes the Rename step when the name changed (Redo applies it again), or the previous step otherwise.
  - The root's name is the ragdoll's name: Save writes it as `meta.name` and suggests it as the file name ([§5.3](05-3-header.md#53-header)).
- **Delete** (Del, or the Delete button) deletes the selected bodies, shapes and joints, wherever focus is (except in text fields, [§5.9](05-9-hotkeys.md#59-hotkeys-defaults)), as **one undo step**. Undo restores everything it removed exactly (same ids, names, order and values, and the same `rootBody`), and Redo removes it again. The deletion cascades:
  - deleting a body also deletes its shapes and every joint connected to it (as `bodyA` or `bodyB`);
  - deleting the remaining shapes of a body deletes the body too, with the same cascade, since a body without shapes is invalid ([§6.4](06-file-format.md#64-validation));
  - every track that targets a deleted shape or joint is deleted with its keys, in every clip;
  - if `rootBody` is deleted, it moves as described in [§2.1](02-object-model.md#21-root-the-ragdoll-itself).

  The root is never deleted: when it is selected with other objects, the others are deleted and the root stays selected; with only the root selected, Delete is unavailable. Selected sprite assets and clips are left alone; they are deleted from the Assets panel and the Timeline. When the timeline's keys or events hold the selection focus, Del deletes those instead ([§5.8](05-8-animation-timeline.md#58-animation-timeline)).
  - **No confirmation**, except when the deletion would remove animation tracks, which Edit mode does not show: then a confirmation states the objects removed and the number of tracks and keys removed, lists the clips affected (each with its own track and key counts), and declining deletes nothing. Undo is the safety net for everything else. The confirmation is a modal dialog shared with New's unsaved-changes confirmation ([§5.3](05-3-header.md#53-header)): Enter or the confirm button confirms, Esc, the Cancel button or a click outside the dialog cancels, Tab stays inside it, and focus returns to where it was.
  - Deleted objects leave the selection. When the focused row is deleted, focus moves to the row that takes its place, or to the last row.
  - Delete is available in Edit mode only ([§5.1](05-1-modes.md#51-editor-modes)), and is unavailable while a drag or scrub is in progress ([§5.9](05-9-hotkeys.md#59-hotkeys-defaults)).
  - The Delete button's tooltip is "Delete (Del)", with the reason when it is unavailable, as in the header ([§5.3](05-3-header.md#53-header)). With only the root selected the reason is "the ragdoll root cannot be deleted": an exception to §5.3's rule of no reason for state, because nothing else tells the user why a selected object cannot be deleted.
- **Duplicate** (Ctrl+D, no button) copies **whole branches**. A body's *branch* is the body and every body that hangs from it through parent joints (each body's parent joint is its tree joint from `rootBody`, or for an unlinked body the first joint in `joints` order that has it as `bodyB`; loop joints are nobody's parent). A joint's *child body* is the body whose parent joint it is; a loop joint has none. The **copied bodies** are the union, each body once, of the branches of: the bodies of the selection as Group defines them ([§2.2](02-object-model.md#22-bodies-and-shapes)), that is the selected bodies plus the body of every selected shape; and the child body of every selected joint. A selected shape therefore copies its whole body, all its shapes included, as Select moves it ([§5.5](05-5-tools.md#55-tools)), and everything hanging from it; Split first to copy part of a body. Duplicating `rootBody` copies its whole linked tree. Selected loop joints, the root, sprite assets and clips add nothing (the root is not a body and is never copied). It is **one undo step**.
  - **Bodies:** each copy has every field of its source (`angle`, `linearDamping`, `angularDamping`, `fixedRotation`, `bullet`) and copies of all its shapes in fixture order, with every shape field (geometry, physics, filter bits, `selfCollide`, `sprite` with the same asset reference, `offset`, `angle`, `scale`, `z`, `visible`). Its `position` is the source's: copies are made **in place**, exactly over their sources, to be moved afterwards. Copies are appended to `bodies` in the sources' `bodies` order. `rootBody` never changes, even when it is copied.
  - **Joints:** a joint is copied when both its `bodyA` and `bodyB` are copied (an *internal* joint, loop joints included; selected or not): the copy references the two copies. A **selected** joint whose child body is copied but whose other body is not is copied too, *re-attached*: its child end references the child's copy and its other end the same, uncopied body, so selecting the wrist joint copies the hand branch still joined to the forearm. A selected joint whose both ends are copied (for example because an ancestor body is also selected) is just an internal joint, copied once. Every copy keeps every other field (limits, motor, `aimAxis`, `collideConnected`), its `anchor` unchanged. Copies are appended to `joints` in `joints` order. Any other joint between a copied and an uncopied body is not copied, so a branch copied from a body shows as unlinked ([§5.6](#56-hierarchy-assets-and-problems-panels)) until joined.
  - **Not copied:** tracks and keys (no clip gains a track), and sprite assets (copies share them).
  - **Ids** are new, from the usual counters (`b_<n>`, `f_<n>`, `j_<n>`, [§1](01-conventions.md#1-conventions)). **Names:** the base is the source's name without a trailing `_copy` or `_copy<k>` (k ≥ 2); the copy takes the first of `<base>_copy`, `<base>_copy2`, `<base>_copy3`, … not used by another object of its kind (bodies, shapes, joints; copies made earlier in the same operation count). Duplicating `arm` gives `arm_copy`, then `arm_copy2`; duplicating `arm_copy` gives `arm_copy2` when `arm_copy2` is free.
  - **Selection:** every selected body, shape or joint that was copied is replaced by its copy, in the same order; other selected objects (the root, uncopied joints, sprite assets, clips) leave the selection. Bodies, shapes and joints copied only because they lie in a copied branch are not selected.
  - Available in Edit mode only ([§5.1](05-1-modes.md#51-editor-modes)) and with at least one body, shape or non-loop joint selected; with only the root (or nothing duplicable) selected Ctrl+D does nothing, with no reason. Unavailable, with no reason, while a drag or scrub is in progress; Undo and Esc still cancel it ([§5.9](05-9-hotkeys.md#59-hotkeys-defaults)).
- **Fit motor torque** (Shift+M, no button) sets `motor.maxTorque` of joints to their suggested torque ([§3.1](03-physics-drive-model.md#31-suggested-motor-torque)), computed on the current document. It acts on the selected joints, or on every joint when no joint is selected (other selected objects are ignored). When no joint is selected, or the root is selected, it also sets `ragdoll.balance.maxTorque` to the suggested balance torque ([§3.2](03-physics-drive-model.md#32-balance-controller-rootbody-orientation)). Joints whose suggestion is `null` and joints already at their suggestion are left unchanged, and so is the balance. It is **one undo step**, recorded only when a value changes; selection is unchanged and nothing is reported. Available in Edit mode only ([§5.1](05-1-modes.md#51-editor-modes)); unavailable, with no reason, while a drag or scrub is in progress. Gain, damping and maxSpeed are not touched.
- **Set as root body** (Shift+R; also the root's `rootBody` dropdown and the body's "Set as root body" button in the inspector, [§5.7](05-7-inspector.md#57-inspector--properties-panel)) makes the body of the selection `rootBody`, converting the root `bodyAngle` keys of every clip as [§2.1](02-object-model.md#21-root-the-ragdoll-itself) states; joints are not changed. The body of the selection is Group's ([§2.2](02-object-model.md#22-bodies-and-shapes)): a selected body, or the body of a selected shape; other selected objects are ignored. It is **one undo step** ("Set as root body"), with no confirmation; selection is unchanged, and the tree re-roots at once, keeping each row's expansion state. Available in Edit mode only ([§5.1](05-1-modes.md#51-editor-modes)) when the selection has exactly one body and it is not already `rootBody`; otherwise Shift+R does nothing, with no reason. Unavailable, with no reason, while a drag or scrub is in progress.
- **Add** menu button, Edit mode only (outside it the button stays focusable and its tooltip gives the mode reason, as in the header, [§5.3](05-3-header.md#53-header); while unavailable it does not open). Choosing an item or Esc returns focus to the Add button. Items:
  - **Add shape:** creates a 0.5 × 0.5 m box shape (the Box tool's default, [`docs/schema.md`](../schema.md)) on a new body at (0, 0) root-local with angle 0, not snapped, named as the Box tool names them ([§5.5](05-5-tools.md#55-tools)). It becomes `rootBody` when `rootBody` is `null`.
  - **Add joint:** creates an unassigned hinge joint at (0, 0) root-local, with no limits and the schema defaults otherwise, named `joint_<n>`. It is listed under Unlinked and is invalid (error) until `bodyA` and `bodyB` are set in the inspector.
  - Each is one undo step and selects what it created, as the creation tools do: the new shape, or the new joint. An active search is cleared first, so the new row is shown. Like Delete, Add is unavailable while a drag or scrub is in progress.

**Assets**
- Lists the sprite assets as thumbnails with their name and `src`.
- **Import** adds images (button or drag & drop).
- **Drag** an asset onto a shape in the viewport or in the Hierarchy to assign it as that shape's sprite.
- **Delete** is blocked while an asset is in use; the panel lists where it is used.

**Problems**: live list of validation errors and warnings ([§6.4](06-file-format.md#64-validation)). Clicking one selects the object.
