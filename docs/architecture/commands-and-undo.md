# Commands and undo

Strategy: **command objects recorded as primitive operations**, not model snapshots ([decision](../decisions.md)). `js/commands/history.js`.

```
Command      { label: string, run(tx: Transaction): * }
Transaction  { model, set(uid, path, value), add(parentUid, collection, index, snapshot) → uid,
               remove(uid), move(uid, parentUid, collection, index) }
Op           { op: 'set',    uid, path, value, previous }
             | { op: 'add',    snapshot, parent, collection, index }
             | { op: 'remove', snapshot, parent, collection, index }
             | { op: 'move',   uid, from: Slot, to: Slot }      Slot = { parent, collection, index }
HistoryState { canUndo, canRedo, undoLabel: string|null, redoLabel: string|null, dirty, gesture: boolean }
```

**`new History(model, { limit = HISTORY_LIMIT } = {})`**, `HISTORY_LIMIT = 200`. Members: `execute(command)`, `undo() → boolean`, `redo() → boolean`, `beginGesture()`, `endGesture() → boolean`, `cancelGesture() → boolean`, `markSaved()`, `state → HistoryState` (getters `canUndo`, `canRedo`, `dirty`, `inGesture` mirror it), `on/off('history')`. History never checks the mode policy; the actions and tools that call it do.

- **Commands are factories** in `js/commands/*.js` that return a `Command` (e.g. `setProps(uids, { 'limits.upper': 1.2 })`). They validate their preconditions and throw before mutating. `index` in `tx.add`/`tx.move` may be `undefined` (append).
- **`history.execute(command) → *`** runs `model.batch(() => command.run(tx))` and returns what `run` returned (e.g. a created uid). Each `tx` call is one `model.applyOps([op])`, applied immediately so `run` reads its own writes; `tx.add` returns the uid from the completed op. History keeps the completed ops each `tx` call returns, which carry their inverse data (`previous`, the removed subtree snapshot with its uids), and the model emits one `change` for the whole command. If `run` throws, the batch reverts the applied ops, nothing is recorded, no event fires and the error is rethrown. An execution with no changes records nothing (outside a gesture, the entry is discarded).
- **Inverse ops** are built by history from the recorded ops (the model's are private): `set` → `set` back to `previous`; `add` → `remove` of `snapshot.uid`; `remove` → `add` of `snapshot` at `parent`/`collection`/`index`; `move` → `move` to `from`.
- **Undo** applies the inverses of the top entry's ops in reverse order with one `model.applyOps(inverses, 'undo')`; **redo** re-applies the entry's recorded ops with one `applyOps(ops, 'redo')` and never calls `run` again, so file ids and uids are identical. Both return `false` (and do nothing) when there is nothing to undo/redo.
- **Compound operations are one command:** delete with cascade (joints, tracks, `rootBody` reassignment), group/ungroup/split, duplicate, create + assign `rootBody`, set key + create track. Whatever `run` does is one undo step.
- **Gestures** merge continuous edits. The tool registry opens one on a primary pointer press and closes it on release; inspector drag-scrubbing and sliders do the same.
  - `beginGesture()` throws if a gesture is already open. Every command executed while it is open is its own batch (one `change`, cause `do`) and appends its ops to the gesture's pending entry, labelled after its first command with changes.
  - **Coalescing:** a `set` op replaces an earlier `set` in the pending entry on the same `uid` and `path` (keeping the earlier `previous` and position, taking the new `value`) only when no op between them is a `set` on the same `uid` whose path is a prefix of that path or has it as a prefix (`sprite` vs `sprite.offset`), or an `add`/`remove` whose snapshot contains that `uid`. Otherwise it is appended. This keeps undo and redo exact when a gesture mixes whole-object and field sets.
  - `endGesture()` records the pending entry and returns `true`, except when it is empty or consists only of `set` ops whose `previous` is JSON-equal to their `value` (a drag back to the start): then nothing is recorded and it returns `false`.
  - A gesture **has changes** when `endGesture()` would record it: its pending entry is not empty and not made only of `set` ops whose `previous` equals their `value`. `canUndo`, `undoLabel` and `dirty` use this criterion, so a drag back to the start counts as no change.
  - `cancelGesture()` applies the inverses of the pending ops with one `applyOps(inverses, 'cancel')` (skipped when there are none), records nothing and returns `true`. Callers: Esc, tool switch, mode change, and `undo()` while a gesture is open, which only cancels it, undoes nothing else and returns `true` like `cancelGesture()`, even for a gesture without changes (the `undo` action is disabled then, since `canUndo` is false). `redo()` while a gesture is open does nothing. Without an open gesture, `endGesture()` and `cancelGesture()` are no-ops returning `false`, so they are always safe to call.
- **Stack:** at most `limit` entries; recording an entry beyond it drops the oldest. Recording an entry clears the redo stack; cancelled and discarded gestures do not, because the model is back where it was.
- **Saved point:** a new `History` treats the model's current state as saved, so a fresh editor is not dirty. `markSaved()` marks the current state as saved. `dirty` is `false` exactly when the model is at the saved state, reached again through undo/redo, and no gesture with changes is open. Once the saved state can no longer be reached (its entry dropped by the limit, or a new entry recorded while it was on the redo stack), `dirty` stays `true` until the next `markSaved()`.
- **Reset:** history listens to the model's `reset` event (there is no public `clear`): it drops an open gesture without reverting it, empties both stacks, and sets the saved point to the new document for causes `new` and `load`, or leaves it unreachable for `recover` (a recovered draft is unsaved).
- **Re-entrancy:** `execute`, `undo`, `redo`, `beginGesture`, `endGesture` (with a gesture open), `cancelGesture` (with a gesture open) and `markSaved` throw while another history call is in progress, i.e. from inside `run` or from a model `change` listener.
  - **Known limitation:** a command executed inside a gesture that removes the open clip makes `modes` emit `mode` from the model's `change` listener, and the editor's cancellation listener then calls `cancelGesture()` with the gesture open, which throws. The command is still recorded into the gesture and the error is rethrown to the caller. No #10 command removes nodes, and gesture owners (tools, scrubbing) only set and add. It is closed by the action rule in [Actions and hotkeys](actions-and-hotkeys.md#actions-and-hotkeys): actions that execute commands are disabled while a gesture is open.
- **Listener errors:** when a model listener throws, the model has already applied the change ([Document model](document-model.md#document-model)). History still updates its stacks as if the call returned (for `execute`, from the ops it kept, once `run` returned), emits `history`, and then rethrows.
- **Event:** `history` with `HistoryState` after any call that changes it, only when it differs from the last one emitted. `canUndo` is true when the undo stack is not empty or an open gesture has changes; `canRedo` when the redo stack is not empty and no gesture is open; `gesture` while a gesture is open. `undoLabel`/`redoLabel` are the labels of the entries undo/redo would act on (the pending gesture's label while one with changes is open).
- **Not undoable:** selection, camera, layout, settings other than `pixelsPerMeter`, mode, playhead, tool. New and Load reset the model, which clears history.

**`setProps(uids, values, label = 'Edit properties') → Command`** (`js/commands/props.js`): `values` maps dotted paths to new values (`{ 'limits.upper': 1.2 }`), the same for every uid; each path is one `tx.set` per uid, in `uids` order. It throws before mutating when `uids` or `values` is empty, a uid is unknown, or a path's first segment is `id` (ids never change, [`DESIGN.md` §1](../design/01-conventions.md#1-conventions)). It does not check types, ranges or references (the inspector constrains input, validation reports the rest, #25). When `name` is set on a clip, key-follows-name ([schema.md](../schema.md#clip-clips)) runs for each clip in `uids` order, with `otherKeys` read after the previous clips of the same command were updated, so renaming several clips at once still yields unique keys; an explicit `key` in `values` wins over the rule.

**`createShapeBody({ position, angle, shape }, label = 'Create ' + shape.type) → Command`** (`js/commands/create.js`) creates one body holding one shape ([`DESIGN.md` §2.2](../design/02-object-model.md#22-bodies-and-shapes)); `run` returns the new **shape** uid, which `history.execute` hands back to the tool.
- **Arguments:** `position` (`Vec2`, root-local m) and `angle` (rad) of the body; `shape` is the shape record around the body origin: `{ type: 'circle', radius }` or `{ type: 'box', width, height }` (#15 adds `{ type: 'polygon', vertices }`). Fields left out (`center`, box `angle`) take their schema defaults (`[0, 0]`, `0`); given fields win.
- **Preconditions** (checked first, before any id is allocated or anything is mutated): `Error` for an unknown or unsupported `shape.type`; `RangeError` when `position` is not a pair of finite numbers, `angle` is not finite, or a size (`radius`, `width`, `height`) is not a finite number above 0.
- **Ops:** ids from `model.nextId('b')` and `model.nextId('f')`; names `body_<n>` and `<type>_<n>`, each `<n>` taken from its own id. One `tx.add(ROOT_UID, 'bodies', undefined, snapshot)` appends `{ type: 'body', props, children: { fixtures: [{ type: 'shape', props }] } }`, where body props are `defaultsOf('body')` without `fixtures` plus `id`, `name`, `position`, `angle`, and shape props are `defaultsOf('shape', type)` plus `id`, `name` and the given `shape` fields merged over the variant defaults. Then, when the root's `rootBody` is `null` or absent, one `tx.set(ROOT_UID, 'rootBody', bodyId)`. So the step is one `add` (body and fixture together) and at most one `set`; undo removes both and restores `rootBody`, redo restores the same ids and uids.
- It does not read the mode policy, the selection or the viewport; the tool does.

**`createJoint({ bodyA, bodyB, anchor, limits }, label = 'Create joint') → Command`** (`js/commands/create.js`, #16) creates one revolute joint ([`DESIGN.md` §2.4](../design/02-object-model.md#24-joints), [§5.5](../design/05-5-tools.md#55-tools) Hinge Joint); `run` returns the new **joint** uid.
- **Arguments:** `bodyA` and `bodyB` are body **uids**, already ordered by the caller (the command never reorders them; the Hinge tool orders them with `orderJointBodies`, [Joint graph](joint-graph.md#joint-graph)). `anchor` is a `Vec2` in root-local meters, rest pose. `limits` is optional, `{ enabled, lower, upper }` in radians; when left out the schema default applies (disabled, 0, 0).
- **Preconditions** (checked first, before any id is allocated or anything is mutated): `Error` when `bodyA` or `bodyB` is not the uid of a `body` node, when `bodyA === bodyB`, or when `jointBetween(model, bodyA, bodyB)` is not `null` (a joint already connects the pair, in either order); `RangeError` when `anchor` is not a pair of finite numbers, or when `limits` is given and `enabled` is not a boolean, `lower` or `upper` is not finite, `lower > 0` or `upper < 0`.
- **Ops:** id from `model.nextId('j')`, name `joint_<n>` with `<n>` from the id. One `tx.add(ROOT_UID, 'joints', undefined, { type: 'joint', props })` appends the joint, where props are `defaultsOf('joint')` plus `id`, `name`, `bodyA` and `bodyB` as the bodies' **file ids** (their `id` props, as references are stored), `anchor` as `[x, y]`, and `limits` when given. Nothing else: `rootBody`, bodies and other joints are untouched. Undo removes the joint (the selection prunes it); redo restores the same id and uid.
- Like `createShapeBody`, it does not read the mode policy, the selection or the viewport. It imports `lib/schema.js` (`defaultsOf`), `js/model/model.js` (`ROOT_UID`) and `js/model/queries.js` (`jointBetween`).

**Transforms** (`js/commands/transform.js`, #17) move and rotate bodies and joint anchors rigidly, in root-local meters and radians ([`DESIGN.md` §5.5](../design/05-5-tools.md#55-tools), Select). A drag never applies deltas to the current model: the tool captures start values at the press and every step executes `placeParts` with absolute values computed from them, so the gesture's `set` ops coalesce into one entry per path, and a drag back to the start leaves no step ([Commands and undo](#commands-and-undo), Gestures). Root `position`/`angle` use `setProps([ROOT_UID], …)`, and `aimAxis` (#24) `setProps([jointUid], { aimAxis })`; no dedicated commands.

```
Parts { bodies: { uid, position: Vec2, angle }[], anchors: { uid, anchor: Vec2 }[] }   frozen; root-local m, rad
manipulationParts(model, { bodies: number[], joints: number[] }, { subtree: boolean }) → Parts
transformParts(parts: Parts, t: Transform) → Parts
rotationAbout(pivot: Vec2, angle: number) → Transform
placeParts(parts: Parts, label = 'Move') → Command
```

- **`manipulationParts`** reads the start values of what a target moves. `M` = the union of `bodySubtree(model, b, parents)` over the given body uids when `subtree`, else the given bodies; when `subtree`, also the subtree of `jointChildBody(model, j, parents)` for every given joint that has a child body (a loop joint has none, so it moves its anchor only), with one `parentJoints(model)` result shared by every call. `bodies`: every body of `M`, in `bodies` order, with `position` (a missing or malformed one reads (0, 0), as in `js/viewport/placement.js`) and `angle` (missing reads 0). `anchors`: in `joints` order, every joint whose `anchor` is a finite pair and that (a) is one of the given joints, (b) is the parent joint of a body in `M`, or (c) is an edge with both bodies in `M`; other joints, including those whose anchor is not placed, are left out. Throws `Error` for a given uid that is not a body (in `bodies`) or a joint (in `joints`). With `subtree: false` the result is a subset of the `subtree: true` one, entry by entry.
- **`transformParts(parts, t)`** applies `t` to every entry: `position' = transformPoint(t, position)`, `angle' = angle + t.angle`, `anchor' = transformPoint(t, anchor)`; results never hold `-0`. Pure; returns new frozen `Parts`.
- **`rotationAbout(pivot, angle)`**: the `Transform` that rotates by `angle` around `pivot`, `{ x: p.x − (cos·p.x − sin·p.y), y: p.y − (sin·p.x + cos·p.y), angle }`. A translation by `d` is `{ x: d.x, y: d.y, angle: 0 }`.
- **`placeParts(parts, label)`** sets each listed body's `position` (`[x, y]`) and `angle`, and each listed joint's `anchor` (`[x, y]`), in list order, skipping every `set` whose value is JSON-equal to the current prop, so a pure move issues no `angle` ops. Preconditions, checked before any mutation: `Error` when a body entry's uid is not a body or an anchor entry's uid is not a joint; `RangeError` for a non-finite number. It does not read the selection, the mode or the viewport.
