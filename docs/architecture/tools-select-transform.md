# Tools: Select transform

**Select transform (#128).** Behavior: [`DESIGN.md` §5.5](../design/05-5-tools.md#55-tools) (Select), [§2.4](../design/02-object-model.md#24-joints) (parent joint and subtree), [§5.4](../design/05-4-viewport.md#54-viewport) (snapping, hover). #17 built these moves and rotations as a separate Manipulate tool (`js/tools/manipulate.js`, `M`); **#128 merges them into Select**: `js/tools/manipulate.js` is deleted, the `manipulate` row leaves `TOOL_SPECS` (so its `tool:manipulate` action, the `M` hotkey row and the toolbar button disappear, and `M` is free), the `tool.manipulate` capability leaves `MODE_POLICY`, and its logic moves to two new core modules used by `js/tools/select.js`. **#24** adds the `aimAxis` handle and sprite edit (`S`) as point handles; **#129** adds resize handles (Select resize, below); **#125** adds Animate rotation (the ring alone, into the parent joint's `angle`). Until #125, Select in Animate mode behaves as in Simulate mode: it selects, every drag draws a box, there is no gizmo and the cursor stays `'default'`.

```
js/tools/manipulation.js   (core; replaces js/tools/manipulate.js)
  manipulationTarget(model, objects: number[]) → Target      moved unchanged; Target { root: boolean, bodies: number[], joints: number[] }
  rotationPivot(model, bodyUid, center: boolean) → Vec2      moved unchanged; root-local m
  lastTargetObject(model, objects: number[], target) → { type: 'root' | 'body' | 'joint', uid } | null
  gizmoPivot(model, objects: number[], { mode: 'center' | 'last', ctrl: boolean }) → Vec2 | null   world m, rest pose
  canRotate(target) → boolean                                root, at least one body, or at least two joints
  startMove(ctx, { target, ref: Vec2, axis: 'x' | 'y' | 'xy', press: ToolPointerEvent }) → Manipulation
  startRotation(ctx, { target, press: ToolPointerEvent, mode: 'center' | 'last' }) → Manipulation
  Manipulation { apply(e: ToolPointerEvent): void, pivot(): Vec2 (world m), readout(): string }

js/tools/transform-gizmo.js   (core; pure, screen px)
  gizmoLayout(pivot: Vec2 (screen), { ring: boolean }) → GizmoLayout
  gizmoHandleAt(layout, screen: Vec2) → 'square' | 'x' | 'y' | 'ring' | null
  drawGizmo(g, layout, { hover: GizmoHandle | null, active: GizmoHandle | null, mode: 'center' | 'last' }) → void
  formatMove(d: Vec2 (world m), pixelsPerMeter) → string     'Δx: 12.0 px  Δy: -3.5 px'
  formatRotation(theta: number (rad)) → string               'Δθ: 15.0°'
```

- **`manipulationTarget(model, objects)`**: `{ root: true, bodies: [], joints: [] }` when `objects` holds `ROOT_UID`; else `bodies` = the selected bodies and the parent body of every selected shape, deduplicated, in first-appearance order of `objects`, and `joints` = the selected joints in `objects` order; other node types are ignored. Pure.
- **`rotationPivot(model, bodyUid, center)`**: the body's `position` (missing reads (0, 0)) when `center`; else the `anchor` of `parentJoints(model).get(bodyUid)` when that joint exists and its anchor is a finite pair; else the body's `position`. Pure.
- **`lastTargetObject(model, objects, target)`**: `{ type: 'root', uid: ROOT_UID }` when `target.root`; else the last uid of `objects`, scanning backwards, that is a body in `target.bodies`, a shape whose body is in `target.bodies` (mapped to `{ type: 'body', uid: body }`) or a joint in `target.joints`; `null` when none. Pure.
- **`gizmoPivot(model, objects, { mode, ctrl })`**, world meters from `placement(model)` (Edit mode shows the rest pose), with `target = manipulationTarget(model, objects)` and `alone(o)` = the pivot of one object: the root position; for a body, `transformPoint(root, rotationPivot(model, uid, ctrl))`; for a joint, its placed anchor (non-finite when unplaced). One object (the root, exactly one body and no joint, or exactly one joint and no body): `alone` of it. Several: `mode === 'center'` → the mean of every target body's world origin and every target joint's placed anchor (unplaced anchors left out); `mode === 'last'` → `alone(lastTargetObject(…))`. `null` when the target is empty or the result is not finite. Pure.
- **`canRotate(target)`**: `target.root || target.bodies.length > 0 || target.joints.length >= 2`.
- **`startMove(ctx, { target, ref, axis, press })`** captures, at the call: the root's start position (root target), or `full = manipulationParts(model, target, { subtree: true })` and `only = …({ subtree: false })` and the root angle. `apply(e)`: `raw = ref + (e.world − press.world)`, with the component across `axis` taken from `ref` (`'x'`: `raw.y = ref.y`; `'y'`: `raw.x = ref.x`); `d = ctx.snapPoint(raw) − ref`, then the component across `axis` set to 0. Root: `setProps([ROOT_UID], { position: [start.x + d.x, start.y + d.y] }, 'Move ragdoll')`. Bodies and joints: `dl` = `d` rotated by −(root angle), `active = e.alt ? only : full`, `values` = `full` with every entry of `active` replaced by its entry in `transformParts(active, { x: dl.x, y: dl.y, angle: 0 })`, then `ctx.history.execute(placeParts(values, 'Move'))`. Entries of `full` outside `active` keep their start values, so pressing ALT mid-drag puts the children back. `pivot()` = the press-time `gizmoPivot` plus the last `d`; `readout()` = `formatMove(d, pixelsPerMeter)` of the last applied event, `pixelsPerMeter` read from the root (`units.pixelsPerMeter`). Everything is recomputed from the start data, never from the previous step.
- **`startRotation(ctx, { target, press, mode })`** captures the root's start `angle` (root target), or `full`, `only`, both world pivots `gizmoPivot(…, { mode, ctrl: false })` and `…{ ctrl: true }` (the body origin moves during the drag, so they are read now), the start root-local angle `a0` of the one target body when the target is exactly one body, and the sweep `{ pivotCenter: press.ctrl, prev: atan2(press.world − P), theta: 0 }`. `apply(e)`: `P` is the pivot of the current `e.ctrl`; when `e.ctrl` differs from `pivotCenter`, `pivotCenter = e.ctrl`, and the sweep restarts (`prev = atan2(press.world − P)`, `theta = 0`) only when the two pivots are at different places; then `φ = atan2(e.world − P)`, `theta += wrap(φ − prev)`, `prev = φ` (`wrap` to (−π, π]; a pointer within 1 CSS px of the pivot on screen leaves both unchanged). Root: `setProps([ROOT_UID], { angle: ctx.snapAngle(start + theta, e.shift) }, 'Rotate ragdoll')`. One body: `θ = ctx.snapAngle(a0 + theta, e.shift) − a0`. Otherwise: `θ = ctx.snapAngle(theta, e.shift)`. Bodies and joints: `active = e.alt ? only : full`, `values` merged as for move from `transformParts(active, rotationAbout(ctx.toLocal(P), θ))`, then `placeParts(values, 'Rotate')`. A shared pivot needs no new command: `rotationAbout` around one root-local point moves every entry rigidly. `pivot()` = the current `P`; `readout()` = `formatRotation(θ)` (root: the snapped angle minus `start`).
- **`gizmoLayout(pivot, { ring })`** in screen px from `GIZMO_SIZE`: X arrow shaft from `pivot + (arrowStart, 0)` to `pivot + (arrowTip − arrowHead, 0)`, head triangle to the tip at `pivot + (arrowTip, 0)`, `arrowWidth` wide; Y arrow the same toward `−y` (up); square from `pivot + (squareOffset, −squareOffset − squareSize)` with side `squareSize`; ring of radius `rotateRing` when `ring`; the pivot itself. **`gizmoHandleAt(layout, screen)`**: `null` within `HIT_RADIUS.root` of the pivot; else, first match: `'square'` (the square grown by 2 px on every side), `'x'` then `'y'` (within `HIT_RADIUS.gizmo` of the segment from `arrowStart` to `arrowTip`), `'ring'` (when present, `|distance − rotateRing| ≤ HIT_RADIUS.gizmo`), else `null`. The areas are disjoint by construction; the order is still fixed. **`drawGizmo(g, layout, { hover, active, mode })`** draws ring, arrows, square, then the pivot mark (reverse hit order), in `COLORS.gizmoX`, `gizmoY`, `gizmoFree` (square fill at 0.4 alpha, 1 px outline), `gizmoZ` (ring, drawn as 32 dashes of half the step, each a `moveTo` and two `lineTo` on the circle, then one `stroke`) and `gizmo` (mark), a handle equal to `hover` or `active` in `0xffffff` with its stroke 1 px wider, using only `moveTo`, `lineTo`, `poly`, `rect`, `circle`, `fill` and `stroke`. **`formatMove`** and **`formatRotation`** round to one decimal, add `0` so a value rounding to zero prints `0.0`, convert with `js/units.js` (`toDisplay(m, 'm', pixelsPerMeter)`, rad → °), and join as `Δx: <x> px  Δy: <y> px` (two spaces) and `Δθ: <a>°`.
- **`selectTool()`** (`id 'select'`, `cursor 'default'`, `hover true`) keeps `{ ctx, press, hovered }` in its closure. `target = manipulationTarget(model, selection.objects)`; the **gizmo is shown** when `ctx.modes.can('edit.rest')`, no box drag is in progress, and `gizmoPivot(model, selection.objects, { mode: settings.get('gizmo.pivot'), ctrl })` is not `null` (`ctrl` of the latest pointer event); during a move or rotation the layout is built at `press.manipulation.pivot()`. Its layout passes `ring: canRotate(target)`. #125 adds the Animate ring.
  - **`handleAt(screen)`**: `null` while the gizmo is not shown; else `'square'` when `gizmoHandleAt` returns it, else the point handles (#24 and #129 add theirs here, hit within `HIT_RADIUS.handle` of their center, nearest center first, ties in list order; within `HIT_RADIUS.root` of the pivot none is returned when `ctx.hitTest(screen)` holds a joint or the root), else `gizmoHandleAt`'s result.
  - **`pointerDown`**, button 0: `handle = handleAt(e.screen)`; a handle → a **handle press** (`'square'`, `'x'`, `'y'` start a move with `axis` `'xy'`, `'x'`, `'y'` and `ref` = the current pivot; `'ring'` starts a rotation with the current pivot mode), the manipulation started at the press and applied only once latched; else `hits = ctx.hitTest(e.screen)`: an **object press** when not empty, else a **box press**. Every press stores `{ kind, start: e, anchor: e.world, hits, dragging: false, last: e }`. Button 2 is ignored.
  - **`pointerMove`** with a press: `last = e`; latch at `DRAG_THRESHOLD` (never unlatches). On the latch of an object press: in Edit mode, when `hits[0]` does not belong to the target (it is not selected, and is not a shape whose body is in `target.bodies`), `ctx.selection.set([hits[0]])` first; then `startMove(ctx, { target: manipulationTarget(…), ref, axis: 'xy', press: start })` with `ref` = `hits[0]`'s body origin (shape), its placed anchor (joint) or the root position (root), all world. Outside Edit mode the object press becomes a box drag. While latched: a manipulation applies `e`; a box drag invalidates the overlay. Without a press: `hovered = handleAt(e.screen)`, the cursor (`'move'` for `'square'`, `'ew-resize'` for `'x'`, `'ns-resize'` for `'y'`, `'pointer'` for `'ring'` and point handles; else `'move'` over a hit in Edit mode; else `null`), and the overlay is invalidated when `hovered` changed or the gizmo depends on CTRL.
  - **`pointerUp`**, button 0, of the press: latch with `e`; a latched manipulation applies `e` once more; a latched box drag runs `applyBox(ctx.selection, ctx.boxTest(boxAabb(anchor, e.world)), e)`; an unlatched object or box press runs the #13 click with `start` and `e`; an unlatched handle press does nothing. Clears the press and the cursor override, invalidates the overlay.
  - **`cancel()`**: drops an open press, clears the cursor override, invalidates the overlay, returns `true` (`false` with no press). The registry then cancels the gesture, restoring every value; a selection made at the latch stays.
  - **`keyDown`** consumes nothing (`S` comes with #24; `Z` is the `pivot-mode` action, not a tool key, so it works wherever focus is).
  - **`readout()`**: while a latched manipulation is in progress, `{ text: manipulation.readout(), screen: last.screen + (16, 16) }`; else `null`.
  - **`drawOverlay(g)`**: a latched box drag draws the #13 rectangle; otherwise, while the gizmo is shown, `drawGizmo(g, layout, { hover: hovered, active, mode })` with `active` the handle of a latched handle press. Nothing else.
- **Overlay refresh:** handles depend on the selection, the document and the pivot mode, so `js/viewport.js` marks the tool overlay dirty on `selection`, `mode`, model `change` and `reset` events (#17) and on `settings` events (#128).

The tool overlay becomes a container holding the `PIXI.Graphics` and one pooled `PIXI.Text` (11 px, `COLORS.gizmo`, the dark outline of the name labels): after `tools.drawOverlay(g)`, `tools.readout()` shows the text at its `screen` point, moved left or up as needed to stay inside the host, or hides it on `null`.

The Settings popover does not show it.

**Select resize (#129).** Behavior: [`DESIGN.md` §5.5](../design/05-5-tools.md#55-tools) (Select, Resize handles; Handles and priority), [§5.4](../design/05-4-viewport.md#54-viewport) (grid snap). Resize handles are point handles of the Select tool, Edit mode only, for exactly one circle or box. One new core module; no new command (`setProps` on the shape, like root moves and `aimAxis`); `js/commands/transform.js` unchanged. Multi-shape resize is not built (decisions, 2026-10-16).

```
js/tools/resize.js   (core)
  resizeShape(model, objects: number[]) → number | null              the shape uid that carries resize handles
  resizeHandles(model, shapeUid) → ResizeHandle[]                     world m, rest pose, tie order
  ResizeHandle { id: ResizeHandleId, point: Vec2 (world m), sign: { x: -1|0|1, y: -1|0|1 }, outward: number (world rad) }
  ResizeHandleId = 'resize-ne' | 'resize-nw' | 'resize-sw' | 'resize-se' | 'resize-e' | 'resize-n' | 'resize-w' | 'resize-s' | 'resize-r'
  resizedBox({ width, height }, q: Vec2, sign, { shift, centered, min }) → { center: Vec2, width, height }   pure, box axes
  resizeCursor(screenAngle: number (rad, Y down)) → 'ew-resize' | 'nesw-resize' | 'ns-resize' | 'nwse-resize'
  startResize(ctx, { shape: number, handle: ResizeHandleId, press: ToolPointerEvent, pivot: Vec2 | null }) → Manipulation
  drawResizeHandles(g, points: Vec2[] (screen), { hover: number | null, active: number | null }) → void
  formatSize(geometry: { width, height } | { radius }, pixelsPerMeter) → string     'w: 50.0 px  h: 25.0 px' | 'r: 12.5 px'
```

- **`resizeShape(model, objects)`**: ignoring uids that are not the root, a body, a shape or a joint: `objects` is one shape, or one body with exactly one child shape; that shape's `shape.type` is `circle` or `box` and `shapeGeometryValid` (`lib/geometry.js`) holds; else `null` (also for the root, any joint, several shapes, polygons). Pure.
- **`resizeHandles(model, uid)`** from `placement(model)` (rest pose): the shape frame `F = bodyWorld ∘ (shape.center, shape.angle)` (circle: angle 0). Box, with `hw = width / 2`, `hh = height / 2`: `ne (+1,+1)`, `nw (−1,+1)`, `sw (−1,−1)`, `se (+1,−1)`, `e (+1,0)`, `n (0,+1)`, `w (−1,0)`, `s (0,−1)` at `F(sign.x·hw, sign.y·hh)`, `outward` = `atan2(sign)` + the frame's world angle. Circle: `r (+1,0)` at `F(radius, 0)`, outward the frame's world angle. Pure; array order is the tie order.
- **`resizedBox(size0, q, sign, { shift, centered, min })`**: `q` is the snapped handle point in box axes relative to the press center. Per axis with `sign ≠ 0`: `size = max(min, centered ? 2·sign·q : sign·q + size0 / 2)`. With `shift`: `k = max(size/size0 over changed axes, min/width0, min/height0)` and both sizes `= k·size0`. Center per axis: changed and not `centered` → `sign·(size − size0) / 2`; else 0. Returns frozen values without `-0`. Pure; the §5.5 example is its test table.
- **`resizeCursor(angle)`**: the angle folded to [0, π) and rounded to the nearest π/4 (π folding back to 0): 0 → `ew-resize`, π/4 → `nwse-resize`, π/2 → `ns-resize`, 3π/4 → `nesw-resize` (screen angles, Y down, so a world +45° outward reads as `nesw-resize`).
- **`startResize(ctx, { shape, handle, press, pivot })`** captures at the call the shape's `shape.center`, `width`, `height` or `radius`, `shape.angle`, the frame `F`, the handle's start `point`, and `min = ctx.snapLength(MIN_SIZE)` with `MIN_SIZE` 0.01 m (`snapLength` returns its input with snap off and never less than the minor spacing with snap on; verify in `js/viewport/snap.js`). `apply(e)`: `h = point + (e.world − press.world)`. Box: `q = F⁻¹(ctx.snapPoint(h))`, `r = resizedBox(size0, q, sign, { shift: e.shift, centered: e.alt || e.ctrl, min })`, then `ctx.history.execute(setProps([shape], { 'shape.center': center0 + rotate(r.center, angle0), 'shape.width': r.width, 'shape.height': r.height }, 'Resize'))`. Circle: `radius = max(min, ctx.snapLength(|h − F(0, 0)|))`, `setProps([shape], { 'shape.radius': radius }, 'Resize')`. Every step from the press values (the gesture coalesces, a drag back leaves no step). `pivot()` returns `pivot` unchanged; `readout()` = `formatSize` of the last applied geometry, `pixelsPerMeter` from the root with the `defaultsOf` fallback.
- **`drawResizeHandles`**: per point an axis-aligned square of `GIZMO_SIZE.resizeHandle` (hover or active: `resizeHandleActive`) centered on it, filled `COLORS.gizmo` (hover or active: `0xffffff`), 1 px outline `COLORS.handleOutline`; only `rect`, `fill`, `stroke`.
- **`js/tools/transform-gizmo.js`**: `drawGizmo(g, layout, { hover, active, mode, points })` gains the optional `points: (g) => void`, called after the arrows and before the square and the pivot mark, so point handles draw between them (reverse hit order).
- **`js/tools/select.js`**: `pointHandles()` = `[]` unless the gizmo is shown, sprite edit is off (#24) and `resizeShape(model, selection.objects)` is a uid; then `resizeHandles(…)` with screen points, recomputed on each call, so they follow the shape during its own drag. `handleAt` tests them as point handles (above). A press on a resize id starts `startResize(ctx, { shape, handle, press: e, pivot: currentPivot(e.ctrl) })`; the cursor over and while dragging it is `resizeCursor` of `−outward` (world to screen flips Y); `drawOverlay` passes `points: (g) => drawResizeHandles(g, …, { hover, active })`. Readout and undo follow the #128 paths unchanged.
- **Style constants** (`js/viewport/style.js`): `COLORS` gains `handleOutline` 0x1b1d21; `GIZMO_SIZE` gains `resizeHandle` 8 and `resizeHandleActive` 10; `HIT_RADIUS.handle` (8) is reused. CSS px.
