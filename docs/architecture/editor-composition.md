# Editor composition

`js/editor.js`: `createEditor({ settings, physics, confirm, notify, files, editorVersion } = {}) → Editor` (frozen; `notify` and `files` from #28) builds, in this order, `model = new Model()`, `history = new History(model)`, `selection = new Selection(model)`, `modes = new Modes(model)`, `camera = new Camera()`, `tools = new ToolRegistry({ model, history, selection, modes, settings, camera }, TOOLS.map((createTool) => createTool()))` and `actions = new ActionRegistry()`, and adds `settings`. `TOOLS` is the module's private list of built tool factories (`circleTool`, `boxTool`); it takes no `tools` option (tests use `ToolRegistry` directly).

- **Editor version (#27):** `createEditor` takes `editorVersion: () => string` (default `() => DEV_VERSION` of `js/version.js`), exposes it as `Editor.editorVersion` and passes it to the registry as `ToolCore.editorVersion`. It is a getter because `js/main.js` learns the version from `version.json` after boot; until then, and when the fetch fails, it is `dev` ([`DESIGN.md` §6.5](../design/06-file-format.md#65-round-trip-guarantee), [Model I/O](model-io.md#model-io)).
- **Cancellation first:** the tool registry subscribes to `mode` in its constructor, before anything else subscribes to `modes` (`settings` and `camera` subscribe to nothing), so its listener, which calls `tools.cancel()` ([Tools](tools.md#tools)), is the first one. `tools.cancel()` cancels the tool and any open gesture, including one the registry did not open (an inspector scrub); the editor has no cancellation listener of its own. Emitters run listeners in subscription order, so other `mode` listeners (Simulate start, #54) never see a half-done gesture.
- **Settings and camera:** `settings` is the given `Settings`, or `Settings.restore(undefined).settings` when omitted, so tests need no storage; anything else given as `settings` throws `TypeError` before anything is built, so a wrong restore result fails at boot instead of at the first `get`. Neither listens to `modes`, and neither is undoable. `js/editor.js` registers no viewport or settings action: `settings`, `frame-selection` and `frame-all` need the DOM or the viewport and are registered by `js/main.js` ([Viewport camera, grid and snapping](viewport-camera-grid-snapping.md#viewport-camera-grid-and-snapping)).
- **Confirmation (#124):** `confirm: (request: ConfirmRequest) => Promise<boolean>` is how core actions ask the user before a destructive step. Omitted, it is `() => Promise.resolve(true)`, so tests and headless use need no DOM; anything else that is not a function throws `TypeError`, checked with `settings` before anything is built. It is not exposed on `Editor`. `js/main.js` passes `(request) => confirmDialog(document, request)` ([Module map: tools and UI](module-map-tools-ui.md)). The typedef `ConfirmRequest` is exported by `js/editor.js`; `confirmDialog` takes the same shape as its options (its own `ConfirmOptions` typedef, so it imports nothing from the core):

  ```
  ConfirmRequest {
    kind:         'delete' | 'new' | 'load'  what asks ('load' from #28). The dialog ignores it
    title:        string            dialog heading
    message:      string            one sentence or two, plain text
    items:        string[]          plain-text list under the message, may be empty
    confirmLabel: string            e.g. 'Delete'
    cancelLabel:  string            e.g. 'Cancel'
  }
  ```

  The wording is built in core (the `delete` request: [Hierarchy and deletion](hierarchy-and-deletion.md#hierarchy-and-deletion)), so it is tested under Node; the dialog only renders it.
- **New (#27):** `new` asks through `confirm` with a `ConfirmRequest` of kind `'new'` (confirm label `Discard`) when `history.dirty`, then `newDocument(model)` (which resets history and selection); a clean document resets without asking. Enabled by `canFile` (below; #28 replaces the `edit.rest` check, which wrongly disabled New in Animate mode, [`DESIGN.md` §5.1](../design/05-1-modes.md#51-editor-modes)).
- **`canFile` (#28):** `modes.can('file') && !history.inGesture && !confirming`; `reason` is the mode reason for `file`, else `null`. Shared by `new`, `load`, `save` and `loadFrom`.
- **Notices (#28):** `notify: (notice: Notice) => Promise<void>` is how core actions report what the user must read, with no Problems panel involved. Omitted, it is `() => Promise.resolve()`; anything else that is not a function throws `TypeError`, checked with `settings`. Not exposed on `Editor`. `js/main.js` passes `(notice) => noticeDialog(document, notice)` ([Module map](module-map.md), `js/confirm-dialog.js`). Actions call it and do not wait for it; a rejection is ignored. Typedef `Notice`, exported by `js/editor.js` (the dialog's own `NoticeOptions` has the same shape without `kind`):

  ```
  Notice {
    kind:       'load-error' | 'load-notes' | 'save-error'
    title:      string             dialog heading
    message:    string             one sentence or two, plain text
    items:      string[]           the first 50 lines, plus 'and N more' when there were more; may be empty
    closeLabel: string             'OK'
  }
  ```

  Wording, built in core (tested): `load-error` "Cannot load file" / "The file has *N errors* and was not loaded. The current ragdoll is unchanged." (items: the errors), or for a read failure "The file could not be read. The current ragdoll is unchanged." (no items); `load-notes` "File loaded with notes" / "The file was loaded. Migrations, dropped fields and warnings are listed below." (items: the migration notes, then the warnings); `save-error` "Cannot save" / "The ragdoll has *N errors*. Fix them and save again." (items: the errors). A problem line is `` `${path}: ${message}` ``, or `message` when `path` is `''` ([`DESIGN.md` §5.3](../design/05-3-header.md#53-header)).
- **Files (#28):** `files: FileService | null` (default `null`). `FileService { openText() → Promise<string | null>, saveText(fileName, text) → void }`: `openText` shows the file picker and resolves the chosen file's text, `null` when the user cancels, and rejects when the file cannot be read; `saveText` starts the download. A non-`null` value without both functions throws `TypeError`, checked with `settings`. Typedef `FileService` exported by `js/editor.js`; `js/main.js` backs it with `js/files.js`. With `files` `null` (tests that do not need it, headless use) `load` and `save` are not registered and report "not available yet"; `loadFrom` exists either way.
- **`Editor.loadFrom(read) → Promise<boolean>` (#28):** the single load path, shared by the `load` action and drops. `read: () => Promise<string | null>` supplies the file text (`null`: nothing chosen). Never rejects. Steps:
  1. `canFile()` false: resolve `false` without calling `read`.
  2. Call `read()` synchronously within the call (the picker needs the click's or key's user activation, so nothing is awaited first). A synchronous throw or a rejection notifies the read-failure `load-error` and resolves `false`; `null` resolves `false`.
  3. `canFile()` false now: resolve `false`. When `history.dirty`, ask with a `ConfirmRequest` of kind `'load'` (title "Discard unsaved changes?", message "Loading a file discards the changes made since the last save. This cannot be undone.", no items, `Discard` / `Cancel`); refused, or `canFile()` false after the answer: resolve `false`.
  4. `loadJson(model, text)`: on `ok: false` notify `load-error` and resolve `false` (model untouched); on `ok: true` notify `load-notes` when `notes` or `warnings` are not empty, and resolve `true`. The reset clears history with its saved point at the loaded document, so it is clean.

  The file is chosen first and the confirmation comes after, for both entry points. No flag is held while `read` is pending (a browser without the input `cancel` event may never settle the picker), so `load` stays enabled meanwhile.
- **Load (#28):** `load` runs `loadFrom(files.openText)`. Enabled by `canFile`; not repeatable.
- **Save (#28):** `save` calls `saveJson(model, editorVersion())` ([Model I/O](model-io.md#model-io)); on `ok: false` it notifies `save-error` and changes nothing; on `ok: true` it calls `files.saveText(fileName, text)` and then `history.markSaved()`, so a throwing `saveText` leaves the document dirty (the error propagates). Warnings are not reported. Enabled by `canFile` whether or not the document is dirty; not repeatable.
- **Tests (#28, `tests/editor.test.js`, fake `files`, `confirm` and `notify`):** `load` and `save` unregistered without `files`; `TypeError` for bad `notify`/`files`; `read` not called when disabled and called synchronously otherwise; Load clean (no confirm), dirty and confirmed, dirty and refused (model unchanged), picker cancelled (`null`), read failure, invalid text (model unchanged, one `load-error` with the error lines), notes and warnings (one `load-notes`), none (no notice), the result clean; Save with errors (no `saveText`, still dirty, one `save-error`), with warnings only (written, clean), the file name passed through; the 50-line cap; `new`, `load`, `save` enabled in Animate, disabled in Simulate, during a gesture and while confirming.
- **Core actions** registered here: `undo` and `redo` (`isEnabled`: `modes.can('history')` and `history.canUndo`/`canRedo`; `reason`: the mode reason when the policy refuses, else `null`; `repeatable`), `escape` (`if (!tools.cancel()) selection.clear()`), and one `tool:<id>` action per registered tool: `run` → `tools.activate(id)`, `isEnabled` → `tools.canActivate(id)`, `reason` → the mode reason for the tool's `capability`. They never execute commands, so they stay enabled during a gesture, and switching tools cancels it. Tools in `TOOL_SPECS` that are not registered have no action, so their hotkey and button report "not available yet". `undo` is unchanged: when it cancels a tool's gesture, the registry sees the gesture close and cancels the tool ([Tools](tools.md#tools)). Actions whose feature is not built are not registered, so they report `'not available yet'`; `new`, `load` and `save` are described above; `play`, `pause`, `next-frame`, `stop` and `toggle-play` arrive with #54, mode switching UI with the Timeline (#32).
