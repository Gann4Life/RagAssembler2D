# Viewport camera, grid and snapping

Behavior: [`DESIGN.md` §5.3](../design/05-3-header.md#53-header) (Settings) and [§5.4](../design/05-4-viewport.md#54-viewport). Everything numeric is core and tested under Node; the DOM and PIXI parts only route events and draw.

| Concern | Core (Node-tested) | UI |
|---|---|---|
| World ⇄ screen, pan, zoom, limits, framing fit | `js/viewport/camera.js` | `js/viewport/input.js` (pointer, wheel, keys), `js/viewport.js` (host size, insets) |
| What is framed | `js/viewport/bounds.js`, `lib/geometry.js` | `js/viewport.js` (`frame(uids)` with `scene.pose()`) |
| Grid levels and lines | `js/viewport/grid-lines.js` | `js/viewport/grid.js` |
| Snapping | `js/viewport/snap.js` | tools, through `ToolContext` |
| Settings values | `js/settings.js` | `js/settings-dialog.js`, `js/storage.js` |
| Display modes | `js/settings.js` (`display.mode`) | `js/viewport/scene.js` |

- **Ownership.** One `Camera` and one `Settings` per editor, owned by the composition root and exposed as `editor.camera` and `editor.settings` ([Editor composition](editor-composition.md#editor-composition)). `js/main.js` restores settings with `Settings.restore(loadSettings().value)` before creating the editor (`restore(undefined)` gives the defaults; a `parse` error and the returned warnings go to `console.warn`) and passes them as `createEditor({ settings })`; it saves with `saveSettings(settings.toJSON())` on every `settings` event.
- **Actions.** `js/main.js` registers the three viewport and settings actions, because they need the DOM or the viewport: `settings` (toggles the Settings popover anchored to the header button; closing it this way returns focus to the button), `frame-selection` (`viewport.frame(selection.objects)`; `frame` falls back to everything when `framingBounds` returns `null`, which covers an empty selection and one with nothing to frame, [`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport)) and `frame-all` (`viewport.frame(null)`). All three are enabled in every mode (`settings.editor` and `camera` capabilities) and never execute commands, so they stay enabled during a gesture. They are registered after `createViewport` resolves, followed by one header refresh; until then they report "not available yet". `F`/`Home` reach them through the existing `HOTKEYS` rows.
- **Insets.** `createViewport` takes `insets: () => Insets`, read at every framing; `js/main.js` returns `framingInsets(toolbar.width())` (`js/viewport/bounds.js`), so the left inset is the overlay's current width (40 or 76 px) plus 16 px ([`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport)). A switch between one and two columns does not reframe; it applies from the next framing.
- **Popover refresh.** The Settings popover follows `settings` events itself, but its document values come through the adapter, so `js/main.js` calls its `refresh()` on `history`, `mode` and model `reset` events ([Editor boot](editor-boot.md#editor-boot)). The popover never subscribes to the model, history or modes.
- **Redraw scheduling.** The grid and the scene mark themselves dirty on events and redraw from a `PIXI.Ticker.shared` callback; `createViewport` inits the application with `sharedTicker: true` so that render runs on the same ticker after them (render is added at low priority). No ticker is passed to `createGrid` or `createScene`; they must only be used inside an application created this way (to be verified, [`DESIGN.md` §12](../design/12-open-items.md#12-open-items--to-verify)).
- **Camera rules.** `zoomAt` clamps `scale` first, then moves `center` so the world point under `screenPoint` stays there. `panBy` moves `center` by the screen delta divided by `scale` (Y flipped). `setSize` keeps `center` and `scale`. `frame(aabb, insets)` picks the largest `scale` that fits the box into the inset rect (at least 1 px each way), clamped, and centers the box in it. `center` is clamped after every operation. Every operation emits one `camera` event when something changed.
- **Snapping in tools.** `ToolContext.snapPoint`, `snapLength` and `snapAngle` are `snap.js` bound to `editor.settings`. Tools apply them as [`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport) lists; the creation tool issues and the Select transform (#17, #128) own that wiring.
