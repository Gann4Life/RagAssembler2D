# Actions and hotkeys

- **`ActionRegistry`** `js/actions.js`: `register(id, ActionSpec)` with `ActionSpec { run(), isEnabled?() → boolean (default true), reason?() → string | null (default null), repeatable?: boolean }`; registering an id twice, an empty id or a spec without `run` throws. `has(id)`; `isEnabled(id)` (`false` when not registered); `reason(id)` → `'not available yet'` when not registered, else the spec's `reason()` while disabled, else `null`; `isRepeatable(id)` (`false` when not registered or `repeatable` is not `true`), read by `dispatchKey`; `run(id) → boolean`, which runs only a registered, enabled action and says whether it ran. `repeatable` is set for `undo`, `redo` and `next-frame` ([`DESIGN.md` §5.9](../design/05-9-hotkeys.md#59-hotkeys-defaults)). Ids reuse the header ids (`new`, `load`, `save`, `undo`, `redo`, `play`, `pause`, `next-frame`, `stop`, `window`, `settings`) and add `toggle-play`, `delete`, `add-shape`, `add-joint`, `group`, `ungroup`, `duplicate`, `key-selected`, `frame-selection`, `frame-all`, `sprite-edit`, `escape`, `tool:<id>`, `panel:<id>` (toggle a panel) and `reset-layout`. DOM-free actions are registered by `js/editor.js`; actions that need the DOM (`window`, `panel:<id>`, `reset-layout`, `settings`, `frame-selection`, `frame-all`) by `js/main.js`; confirmations, notices and file I/O reach core actions through the `confirm`, `notify` and `files` options of `createEditor`, so `new`, `load` and `save` are core actions (#28, [Editor composition](editor-composition.md#editor-composition)). The existing `Ctrl+O` and `Ctrl+S` rows reach `load` and `save` with no hotkey change ([Editor boot](editor-boot.md#editor-boot)). The header and hotkeys both call `run`; the header refreshes `aria-disabled` and its tooltip from `isEnabled` and `reason` on `history`, `mode` and `selection` events.
- **No commands during a gesture:** every action that executes a command (`delete`, `add-shape`, `add-joint`, `group`, `ungroup`, `duplicate`, `key-selected`, …; not `undo`, `redo`, `escape`) reports `isEnabled() === false` with `reason` `null` while `history.inGesture`. Only the gesture owner (the tool registry, an inspector scrub) executes commands inside its gesture. This keeps a key pressed mid-drag out of the drag's undo step and rules out the cancellation re-entrancy described in [Commands and undo](commands-and-undo.md#commands-and-undo). The header is not refreshed on gesture start, which is harmless: the pointer is captured by the drag, and `run` re-checks `isEnabled`.
- **`HOTKEYS`** `js/hotkeys.js`: frozen `Hotkey { keys, action }` rows for §5.9 in table order (`{ keys: 'Ctrl+Shift+Z', action: 'redo' }`, `{ keys: 'Ctrl+Y', action: 'redo' }`, `{ keys: 'Space', action: 'toggle-play' }`, …); #12 puts first one `tool:<id>` row per `TOOL_SPECS` entry, built from its `hotkey` (`{ keys: 'V', action: 'tool:select' }`, …), for every tool whether registered or not. `keys` is `[Ctrl+][Shift+][Alt+]<key>`, where `<key>` is an upper-case letter, a digit, `.`, `Space`, `Del`, `Esc` or `Home`. The header's shortcut hints must equal this table (tested): for each header action with a hint, its rows joined with `' / '` in table order, `play` and `pause` reading the `toggle-play` rows.
- **`matchHotkey(event) → ActionId | null`**: `Meta` counts as `Ctrl`; `event.key` is compared case-insensitively for letters (`Del` = `Delete`, `Esc` = `Escape`, `Space` = `' '`); Ctrl, Shift and Alt must match the row exactly, so `Ctrl+Z` never matches with Shift held.
- **`dispatchKey(event, { tools, actions, viewportFocused }) → boolean`** (`tools` is `editor.tools`; `null` is accepted and skips step 2) order:
  1. ignore if `event.defaultPrevented` (a focused widget handled the key) or the target is a text field (`input` other than checkbox, radio, range, button types), `textarea`, `select` or `isContentEditable`;
  2. if the viewport has focus, `tools.key(e)`; stop if consumed;
  3. `matchHotkey(e)`; on a match, `preventDefault` (even when the action is disabled, so the browser's shortcut never fires), then, unless `event.repeat` and `actions.isRepeatable(id)` is `false`, `actions.run(id)`. Space only matches when `viewportFocused` or the target is the page `body`, and the viewport turns Space into pan-or-toggle ([`DESIGN.md` §5.9](../design/05-9-hotkeys.md#59-hotkeys-defaults)).
  
  It returns `true` when the key was consumed (by a tool or a match). It reads only properties of `event` and its target; it never touches `document`.
- `escape` runs `tools.cancel()`, and clears the selection when nothing was cancelled ([Editor composition](editor-composition.md#editor-composition)). `tool:<id>` runs `tools.activate(id)`; a switch during a drag cancels the drag ([Tools](tools.md#tools)).
