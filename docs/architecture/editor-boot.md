# Editor boot

1. `index.html` loads `css/editor.css`, then the vendored libraries as classic scripts: `vendor/pixi.min.js` (defines `PIXI`) and `vendor/liquidfun.js` (defines `Box2D`).
2. It loads `js/main.js` as the only module script. The markup holds a placeholder `<header id="header">` and `<main id="workspace">` with the viewport panel (`#panel-viewport` > `#viewport-host`, `role="group"`, `tabindex="0"`, labelled "Viewport"; [`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport)). The viewport switches the host to `role="application"` once it handles keys (step 11).
3. `js/main.js` reads the `PIXI` and `Box2D` globals and throws an `Error` naming the missing library and its `vendor/` file. The error only reaches the console; the page stays blank.
4. It restores the editor settings with `Settings.restore(loadSettings().value)`: a `parse` error and every returned warning go to `console.warn`, and `missing`/`unavailable` give the defaults silently.
5. It calls `createEditor({ settings })` ([Editor composition](editor-composition.md#editor-composition)): model, history, selection, modes, the tool registry, the core and `tool:<id>` actions, the settings and the camera, without DOM. It saves with `saveSettings(settings.toJSON())` on every `settings` event.
6. It replaces the placeholder with `createHeader(document)`: a toolbar with every action disabled ([`DESIGN.md` §5.3](../design/05-3-header.md#53-header)). The Settings button gets `aria-haspopup="dialog"` and `aria-expanded="false"`.
7. It creates the dock with `createDock(#workspace, { viewportElement: #panel-viewport })`, which restores the stored layout (falling back to the default layout if restoring throws) and renders every stack, with placeholders for the panels ([Dock layout](dock-layout.md#dock-layout)).
8. It registers the DOM actions on `editor.actions`: `window` (toggles `openMenu(windowButton, dock.windowItems(), …)` on its first item), one `panel:<id>` per `PANELS` entry (opens or closes the panel) and `reset-layout`. Choosing a Window menu item calls `actions.run('panel:<id>')` or `actions.run('reset-layout')`; Left/Right from the menu call `focusAdjacentAction(header, windowButton, key)`. Down and Up on the Window button open the menu on its first or last item (handled on the button, not as actions).
9. It refreshes every header button with `setActionEnabled(button, actions.isEnabled(id), actions.reason(id))`, once and then on every `history`, `mode`, `selection` and model `reset` event, and routes every `header-action` to `actions.run(id)`. On `history`, `mode` and `reset` it also calls `refresh()` on the open Settings popover, so its pixels per meter value and read-only state follow undo, mode changes and gestures.
10. It adds one `keydown` listener on `document` that calls `dispatchKey(event, { actions, tools: editor.tools, viewportFocused })`, where `viewportFocused` means focus is inside `#viewport-host` ([Actions and hotkeys](actions-and-hotkeys.md#actions-and-hotkeys)).
11. It awaits `createViewport(PIXI, #viewport-host, { model, camera, settings, selection, modes, tools, insets, onSpaceTap: () => actions.run('toggle-play') })` ([Viewport camera, grid and snapping](viewport-camera-grid-snapping.md#viewport-camera-grid-and-snapping)), which binds the tool registry to the view and stacks the gizmo and tool overlay layers; `insets` returns `framingInsets(toolbar.width())`, 16 px on every side plus the Tools overlay width on the left.
12. It registers `settings`, `frame-selection` and `frame-all`, then refreshes the header once more.

`Box2D` is checked but not used yet. The DOM actions are registered in `js/main.js` because they need the dock, the header or the viewport; `js/editor.js` registers only DOM-free actions.

Tools overlay ([`DESIGN.md` §5.5](../design/05-5-tools.md#55-tools)):
- Right after `createDock` (step 7) and before `createViewport` (step 11), `js/main.js` calls `createToolbar(#panel-viewport, { host: #viewport-host, onActivate: (id) => actions.run('tool:' + id) })`, which inserts the toolbar before the host, so it exists before the viewport frames on start.
- It refreshes the toolbar once at start and on every `tool` and `mode` event: `toolbar.setActive(tools.active?.id ?? null)` and, for every `TOOL_SPECS` id, `toolbar.setEnabled(id, actions.isEnabled('tool:' + id), actions.reason('tool:' + id))`. A tool that is not registered has no action, so it reports `'not available yet'`.
- Step 11 passes `insets: () => framingInsets(toolbar.width())`.

Hierarchy: right after `createDock` (step 7), `js/main.js` calls `createHierarchy(dock.panelElement('hierarchy'), editor)`, which replaces the placeholder content of that element ([Hierarchy and deletion](hierarchy-and-deletion.md#hierarchy-and-deletion)). The panel element exists while the panel is closed, so the Hierarchy is created once and keeps its state across close and reopen.

**(planned, #28)** Files: step 5 also passes `notify: (notice) => noticeDialog(document, notice)` and `files: { openText: () => pickTextFile(document, RAG_FILE_ACCEPT), saveText: (name, text) => downloadText(document, name, text) }` to `createEditor`. Right after `createDock` (step 7) it calls `attachFileDrop(#panel-viewport, (read) => editor.loadFrom(read))` (the panel, so drops on the Tools overlay load too) and `blockFileNavigation(document)`. The header and `Ctrl+O`/`Ctrl+S` already route to `actions.run('load' | 'save')`.
