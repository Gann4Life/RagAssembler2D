# View sync

`js/viewport/scene.js` never rebuilds the scene on a change. Built with #11: layers, camera transform, root, body and shape entries, display modes and the pose override. Sprite entries come with #21, and FK re-evaluation with the Animate issues. Joints, gizmos and highlights are not scene entries: they are drawn by `js/viewport/gizmos.js`.

- It keeps `Map<uid, Entry>` for root, bodies and shapes (sprites from #21). Stage order, bottom to top, stacked by `js/viewport.js`: grid (`js/viewport/grid.js`, screen space), scene view (its world container holds sprites (flat container, `sortableChildren`, `zIndex = z`, because z is ordered across the whole ragdoll) and shapes (root container → body containers → shape graphics)), gizmo layer (`js/viewport/gizmos.js`, screen space: feedback outlines, root and joint gizmos, overlays) and tool overlay (screen space, the active tool's `drawOverlay`).
- On `change`: `add` creates the entry, `remove` destroys it, `move` reparents it, `set` marks it dirty with the smallest effect: root or body transform → container transform plus that body's sprites; shape geometry or `editor.color` → redraw that shape; `sprite.*` → that sprite; `units.*` on the root → world container re-placed and every entry dirty (still no rebuild). Joint changes touch no scene entry; the gizmo layer redraws on every model `change`. Clip, track, key and event changes only re-evaluate the FK pose when they belong to the open clip in Animate mode.
- Dirty entries are flushed once per frame from `PIXI.Ticker.shared`, which the viewport's application also renders from (`sharedTicker: true`), so a flush always precedes the render of its frame. `reset` is the only full rebuild; it clears the pose override, and the scene's `reset` listener runs before the viewport's, so framing after a reset uses the rest pose.
- Malformed shapes (non-finite numbers, non-positive radius, fewer than 2 polygon vertices, unknown type) draw nothing; an invalid `editor.color` falls back to the schema default; an invalid `pixelsPerMeter` falls back to the schema default for display.
- Conversion follows [`DESIGN.md` §1](../design/01-conventions.md#1-conventions): `x·ppm`, `−y·ppm`, `rotation = −angle`. The world container holding the sprite and shape layers carries the camera: `scale = camera.scale / ppm` and position `(width/2 − center.x·camera.scale, height/2 + center.y·camera.scale)`, so pan and zoom never redraw entries. The grid, gizmo and tool overlay layers are in screen space and are redrawn from a `PIXI.Ticker.shared` callback, at most once per frame, when dirty (a camera change included); they keep constant CSS px sizes without depending on the scaled-stroke technique.
- Outlines stay 1 CSS px at every zoom: shapes are stroked with width `ppm / camera.scale` (local units) and redrawn, once per frame, when `camera.scale` changed since the last draw (to be verified, [`DESIGN.md` §12](../design/12-open-items.md#12-open-items--to-verify)).
- `setPose(pose | null)` overrides body transforms (a root-local `Pose`, `js/viewport/bounds.js`) for FK preview without touching the model; `pose()` returns the current override, which framing, hit testing and gizmos use (whoever calls `setPose` also calls `gizmos.invalidate()`). Simulate mode shows the `RagInstance` view instead (#54), and also sets the live root-local body transforms as the pose every frame, so hover, selection and gizmos follow the bodies. The preview environment (ground line, pin `rootBody`, gravity; [`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport)) is built with Simulate mode (#54) and Pose (#38), not with #12.
- `display.mode` sets layer visibility and the shape style ([`DESIGN.md` §5.4](../design/05-4-viewport.md#54-viewport)) and redraws shapes; it never touches the model or hit testing. Shapes: sprites layer hidden, shapes filled at 0.4 and stroked at 1. Both: sprites shown, shapes stroked at 0.6 without fill. Sprites: the whole shapes layer is hidden, so the hover and selection outlines that §5.4 keeps in this mode are drawn by the gizmo layer, which draws them in every display mode.
- Selection, hover, mode and settings changes redraw gizmos and highlights only.
